# Home Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans, plus the model-orchestration skill. TDD throughout (failing test, then minimal code). `Decimal`, never `float`, for every money, units and NAV value. **No code starts until the owner says go.**

**Goal:** thin FastAPI endpoints and pure service functions that give the Home screen its data, built on existing tables and code. Spec: `Docs/orchestration/2026-10-23-home-functionality-backend-spec.md`. Decisions BD1-BD17: `2026-10-23-home-backend-decisions-proposal.md`.

**Decisions this plan relies on:** B2 (price movement only), B5 (gain excluding new money, Modified Dietz), L21/L47 (sector view is a labelled pro-rata estimate), L25/L45 (benchmarks incl. Nifty Smallcap 250), L48 (time-of-day greeting from IST, nothing stored), L44/L49 (data line only), P7 A (Home uses stored prices, no live download), P9 A (Dashboard untouched), H6/N1 (retention 6 months), H18 (new `api/home.py`), BD12 (opening-balance cache fix). **Tracking is deferred and not in this plan.**

**Branch:** `feat/home-snapshot` from updated `feat/leapswitch-staging`. Touch only new files plus the small existing-code changes listed in T1-T4. No commit or push without the owner's word.

**Test commands:** `cd backend && .venv/Scripts/python.exe -m pytest <file>` (Postgres-only behaviour in `tests/functional_postgres`). No live network in tests.

## Risks

Holdings cache is per web worker (three workers, 15-minute life). Sector view depends on disclosure freshness (about 10 days old, up to 40), hence the label. A wrong stale-price rule could show a price a day old (stored prices are up to about 10 hours behind between the evening NAV publish and 06:00). Retention growth (check size).
