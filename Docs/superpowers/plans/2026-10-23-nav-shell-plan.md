# Navigation Shell Implementation Plan (PR 1 and PR 2)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans, plus the model-orchestration skill (Codex worker, adversarial review gate). Steps use checkbox (`- [ ]`) syntax. TDD: write the failing test, watch it fail, then the minimal code. **No code starts until the owner says go.**

**Goal:** a desktop router, route registry, two-mode sidebar, top bar and family-or-member scope provider, exactly as `Docs/orchestration/2026-10-22-nav-shell-contract-v1.md` (v1.2) and `2026-10-22-nav-shell-architecture.md` describe. Mobile, print, legal and existing screens are untouched; existing screens are wrapped by thin route files and never edited.

**Decisions this plan relies on:** L29-L33, L35, L38, L43, L46 (search on hold: the box keeps its place, builds nothing), M17 (links to unbuilt pages stay greyed with a "Coming soon" tooltip), H17 (slug `direct-stocks`), FDs & bonds under Equity, Mutual Fund and US Stock separate items, react-router `^7.18.4`.

**Branches:** PR 1 `feat/shell-nav` (T1-T7, not switched on). PR 2 (T8-T10, switches on). Both from `feat/leapswitch-staging`, label `shell-contract`, CODEOWNERS review by both owners. PR 1 merges first. No commit or push without the owner's word.

**Cross-checked 2026-10-23 against** `Docs/orchestration/2026-10-22-left-panel-plan.html` (the Left Panel Plan workbook; this plan implements its sidebar decisions and its delivery steps 1 to 7, with its "Later" items as PR 2). Effort from that workbook: about 7 to 8 developer-days for PR 1 (an estimate, not measured). Differences found and resolved are in the last section.

**Tech:** React 19, Vite 8, Tailwind 3.4, lucide-react 0.475, vitest, react-router 7.

## Risks

State move from `MainDashboardFlow` changes behaviour (mitigation: port tests first, move not rewrite). A route file breaks the whole menu (contract test fails loudly). react-router API differs from the declarative assumption (verify in T1, adjust the architecture doc). Real URLs without server fallback (Caddy and CloudFront already fall back to `index.html`; add a note to the deploy guides).
