### 1. The API (`frontend/src/features/export/api.ts`, new; follow how `features/import/api.ts` or `features/mutual-funds/api.ts` call the server: the shared `apiClient`/`cachedFetch` helpers, the bearer from `getToken()`, `ApiError`)
`createExport(options: { scope: string; section_ids: string[]; cover: boolean; data_dates: boolean; show_folios: "full" | "masked" | "none" }): Promise<{ job_id: string; status: string }>` (POST `/export/report`; **409** body `{ code: "export_in_progress", job_id }` and **429** body `{ code: "export_cooldown" }` are returned as typed errors `ExportInProgressError(jobId)` and `ExportCooldownError`); `getExportStatus(jobId): Promise<ExportJobStatus>` (`status: "preparing"|"ready"|"failed"|"cancelled"`, `stage: "collecting"|"building"|"finishing"`, `sections_total`, `scope_kind`, `error_code`, `pdf_bytes`); `downloadExportFile(jobId): Promise<{ blob: Blob; fileName: string }>` (GET `.../file` with the bearer, **read as a blob**, the file name from the `Content-Disposition` header, falling back to `Unifolio-portfolio-report.pdf`; **404 means already downloaded or expired**); `cancelExport(jobId): Promise<void>` (DELETE). **Never put the PDF, a job id or a scope in the URL of a page or in `localStorage`.** These are the only network calls in `features/export`: **update `export.guard.test.ts`'s "no network call" rule to allow exactly `api.ts` (and the hook file below), nothing else.**
### 2. The job hook (`frontend/src/features/export/useExportJob.ts`, new)
`useExportJob(): { state: "idle"|"preparing"|"ready"|"failed"; progress: { subtitle: string; percent: number; rows: StageRow[] }; ready: { fileName: string; chips: string[] } | null; failed: { code: string | null; canTryFewer: boolean; canExportMember: boolean }; start(choice: ExportChoice, labels: { scopeLabel: string; presetLabel: string }): Promise<void>; cancel(): void; reopen(): void; reset(): void; downloadAgain(): void; lastChoice: ExportChoice | null }`. Behaviour: `start` maps the choice to the API body (`who` `"family"` is `scope: "family"`, a member id is `scope: <id>`; `showFolios` true is `"full"`, false is `"masked"`), calls `createExport`, then **polls `getExportStatus` every 2 seconds** until `ready`, `failed` or `cancelled` (stop polling on unmount and on cancel; a poll network error is retried up to 3 times then the job is `failed` with code `null`). **Progress rows** use the dialog's five rows and words (they are in the packet; reuse the exact strings from the drawing): while `collecting`: row 1 `now`; `building`: rows 1 and 2 `done`, row 3 `now` with the note `<sections_total> sections` (new wording: use the dialog's own `14 of 26 sections` pattern **only with the total**, e.g. `26 sections`); `finishing`: rows 1 to 3 `done`, row 4 `now`; the **percent** is 15, 55, 90 for the three stages and 100 when ready; the row 2 note is today's prices date if the front end knows it, otherwise no note (do not invent a date). `progress.subtitle` = `<scope label> · <preset label> · <n> sections`. **When the job becomes `ready` the hook downloads the file once** (`downloadExportFile`), keeps the `Blob` in memory, **starts the browser download** (an object URL on an anchor with `download = fileName`, clicked, then revoked after a short delay), and sets `ready.fileName` and `ready.chips` = `[<size>, <scopeLabel>, <presetLabel>]` where the size is `pdf_bytes` shown as `0.9 MB` or `812 KB` (**compute with integer maths: no `toFixed`, `parseFloat` or `Intl` in `features/export`**). **`downloadAgain()` re-triggers the download from the kept blob** (the server serves the file only once). `failed.canTryFewer` is true when more than one section was requested; `canExportMember` is true for a family report in a household with more than one member. `ExportInProgressError` on `start` attaches to that job (polls it) instead of failing. `ExportCooldownError` gives `failed` with `error_code: "cooldown"`. An `error_code` of `busy` or `timeout` or `too_large` or `print_error` or `internal` becomes `failed.code` as a **short display code** (a fixed map: `busy` is `EXP-BUSY`, `timeout` `EXP-TIME`, `too_large` `EXP-SIZE`, `print_error` `EXP-PAGE`, `internal` `EXP-FAIL`, cooldown `EXP-WAIT`; these are the dialog's "quote this code" values, **flag them as new wording**). `cancel()` calls `cancelExport` and returns to `idle`. `reopen()` is used by the top-bar button while preparing.
### 3. The fallback page (`Print it from your browser instead`)
The print route accepts a second mode: the fragment `#mode=browser&opts=<base64url(JSON)>` (**no `pass`**): `printFragment.ts` accepts a missing `pass` **only** with `mode=browser`; `PrintReport` then does **not** call `setTokenOverride` (the user's own session token from `getToken()` is used by the section hooks, exactly like the screens), and **after the ready marker it calls `window.print()` once** (a small centred line `Preparing your report. When it is ready the print window opens: choose Save as PDF.` shown **on screen only**: new wording, flag it; hidden in print). The dialog's fallback row opens `/print/report#mode=browser&opts=...` **in a new tab** (`window.open(url, "_blank", "noopener")`); the options object is built exactly as the server builds it, including `members` and `meta`: build `members` from the shell's scope members and `meta` from the signed-in account (`useAuth().me`: the holder's name is the self member's name the shell already knows; if there is none, `holderName: null`; `scopeName` is the holder's name for a family report with a holder, `"Your family"` without, the member's name for a member report; `memberCount` accordingly) in a small pure function `buildPrintOptions(choice, scope, me)` in `features/export/` with tests. The pass is **not** involved in this mode.
### 4. Mounting the dialog (`frontend/src/features/export/ExportHost.tsx`, new, and one edit in `frontend/src/shell/layout/TopBar.tsx`)
`ExportHost` renders `ExportButton` and `ExportDialog` and owns `open` state and `useExportJob`. `TopBar` replaces its `<ExportButton ... onOpen={() => undefined} />` with `<ExportHost />` (the only change to `TopBar.tsx`). `ExportHost` reads: the household `members` from `useScope()` (`{ id, name }`), `currentTab` from the route (a Mutual Funds tab id from the pathname: use the registry/route helper the shell already has (`resolveRoute`/`paths`), `null` on every other page), `defaults.showFolios` from `useFolioVisibility()` (on unless the user hid folios), `defaults.who` `"family"` (or the only member), `defaults.preset` `"tab"` when `currentTab` is not null else `"full"`. The button's `busy` is `job.state === "preparing"`; `onOpen` opens the dialog on `stage` = `choose` (idle), `preparing`, `ready` or `failed` according to `job.state`. Stage and callbacks: `onStart` -> `job.start(choice, labels)` (labels: `scopeLabel` is `Family combined` or the member's name, `presetLabel` is `Full report`, `This tab` or `Custom`, **reuse the dialog's own chip words**); `onCancel` -> `job.cancel()` and close; `onKeepWorking` -> close the dialog (the job continues, the button shows `Preparing…`); `onDownloadAgain` -> `job.downloadAgain()`; `onExportAnother` -> `job.reset()` then stage `choose`; `onDone` -> close and `reset`; `onTryAgain` -> `job.start(job.lastChoice, ...)`; `onFewerSections` -> `reset` and open `choose` with the `This tab` preset (or `Custom` when there is no current tab); `onPrintInstead` -> the fallback of section 3; `onExportMember` -> `reset` and open `choose` with the first member preselected; `onClose` -> close and `reset`. **When the dialog is closed and the job becomes ready, the download still starts (the hook does it) and the button returns to rest; the next open shows `ready`.** `useHasFunds()` (the placeholder): return `false` when `useScope().members` is empty, otherwise `undefined` (unknown means the button is enabled).
