## The job in one paragraph
Today `backend/app/services/analytics/pdf_export.py` starts one Chromium **per worker process at start-up** (`main.py` lifespan) and keeps it forever. The new export (Batch I) must start a browser **only when an export is running**, run **at most two exports at once across the whole backend container**, allow **one export per user at a time**, add a **15-second cooldown per user**, close the browser after a quiet period, and always release everything if an export fails or is cancelled. The backend runs **three uvicorn worker processes** (`--workers 3`), so a counter in memory is wrong (three processes would allow six exports, and one user could run three at once): the limits must hold **across processes**. The old pipeline and its start-up browser stay exactly as they are (the old export route must keep working for the old staging link); the new pool sits beside it and starts nothing at start-up.

## Design (decided; build to it)
New file `backend/app/services/export/browser_pool.py` (create the package `backend/app/services/export/` with an empty `__init__.py`). Constants: `MAX_CONCURRENT_EXPORTS = 2`, `USER_COOLDOWN_SECONDS = 15`, `IDLE_CLOSE_SECONDS = 120`, `SLOT_WAIT_SECONDS = 60`. Exception `ExportBusyError(Exception)` with a `reason: Literal["user_busy", "cooldown", "slots_full"]`.
**Cross-process state lives in small files under a lock directory** (all three workers share the container's file system; no database, no migration, no network, no new dependency): setting `export_lock_dir: str = "/tmp/unifolio-export"` in `backend/app/config.py` (env `EXPORT_LOCK_DIR`), created on first use with mode `0o700`.
- **Slots:** files `slot-0` ... `slot-(MAX-1)`; a slot is claimed by a **non-blocking exclusive `fcntl.flock`** on it and released by closing the file (the operating system releases it if the process dies, so a crashed export never leaks a slot).
- **One export per user:** a file `user-<first 16 hex of sha256(user_id)>.lock`, same non-blocking exclusive flock; if it cannot be taken: `ExportBusyError("user_busy")`.
- **Cooldown:** a file `user-<same hash>.done` whose modification time is touched when that user's export ends (success, failure or cancel); if `now - mtime < USER_COOLDOWN_SECONDS`: `ExportBusyError("cooldown")`.
- **Waiting for a slot:** when both slots are taken, the caller **waits** (poll every 0.25 s, with `asyncio.sleep`) up to `SLOT_WAIT_SECONDS`, then `ExportBusyError("slots_full")`. (The user lock is taken **first**, the slot second, so a waiting user already counts as "busy".)
- **The browser:** **one browser per process**, started lazily when the first export in that process holds a slot, guarded by an `asyncio.Lock`, shared by that process's concurrent exports; closed by a timer `IDLE_CLOSE_SECONDS` after the process's last export ended (cancel the timer when a new export starts); closed at shutdown by `close_pool()`.
- **Interface:** `async with acquire_browser(user_id: uuid.UUID) as browser:` yields a `PooledBrowser` wrapper with `async new_page()` that **records every page it hands out**; on exit (normal, error **or `asyncio.CancelledError`**) the pool closes any page still open, releases the slot and the user lock, touches the `.done` file, and starts the idle timer. `close_pool()` (async) closes the browser and cancels the timer.
- **Seams for tests (no real Chromium, no real locks needed in most tests):** `set_browser_factory(factory)` where the factory is an async callable returning an object with `new_page()` and `close()` (default: Playwright's `async_playwright().start()` then `chromium.launch()`, imported lazily inside the factory); `set_slot_backend(backend)` where `backend` follows a small `SlotBackend` protocol: `try_claim_slot() -> handle | None`, `release_slot(handle)`, `try_lock_user(user_key: str) -> handle | None`, `release_user(handle)`, `last_done_age(user_key: str) -> float | None`, `mark_done(user_key: str)`. The default `FlockSlotBackend` imports `fcntl` **inside** its constructor (so importing the module on Windows works) and raises `RuntimeError` there if `fcntl` is missing. Tests inject an in-memory `FakeSlotBackend` (written in the test file) and a controllable clock (a `set_clock(fn)` seam for the cooldown and idle timer).
- **Lifespan:** in `backend/app/main.py` add **only** `await close_pool()` after `await stop_browser()` in the shutdown part of `lifespan` (an import line and one call). Do not remove or change `start_browser`/`stop_browser` (the old pipeline keeps using them).

## Tests first (`backend/tests/services/export/test_browser_pool.py` and `__init__.py` beside it; invented data; written and run before the code)
With the fakes: `test_one_browser_started_on_first_use` (the factory is called once for two exports in the same process); `test_two_at_once_third_waits` (the third `acquire_browser` does not enter until one of the first two leaves, then enters); `test_third_waiter_gets_slots_full_after_the_wait_limit` (with a clock that jumps); `test_same_user_second_export_rejected` (`user_busy`); `test_cooldown` (a second export for the same user within 15 s is `cooldown`, after 15 s it is allowed); `test_browser_closes_after_quiet_period` (idle timer with the fake clock; a new export before the deadline cancels it); `test_failed_export_closes_its_page` (an exception inside the block still closes the page it opened and releases the slot); `test_cancelled_export_releases_slot` (cancel the task while it holds a slot; the slot and the user lock are free afterwards); `test_user_lock_released_so_next_user_can_run`; `test_close_pool_closes_the_browser_and_is_safe_twice`; `test_old_pipeline_start_browser_untouched` (import `app.services.analytics.pdf_export` and assert `start_browser`, `stop_browser`, `get_shared_browser` still exist and the module did not import the pool). **One real-lock test, skipped where `fcntl` is missing** (`pytest.mark.skipif(sys.platform == "win32", ...)`): `test_flock_backend_limits_hold_across_processes` using the real `FlockSlotBackend` with `tmp_path` as the lock directory and **two child processes** (`multiprocessing`) that each try to claim a slot while the parent holds the other: with `MAX=2`, the third claim across all three processes fails, and when a child exits (even killed) its slot is free again.
