## What IF-B1 leaves in place for IF-B2 (already in the branch when IF-B2 starts)
- `types.ts`: `ScatterPointOut.held?: boolean` (additive, optional, register C124); the `scatter` and `scatter_thin` fixtures carry `held` (the fund's own dot and exactly one peer are held, the others are not). A dot with `held` absent is "not known": it does not link.
- `fundCopy.ts`: `unavailableText` already words `no_manager_data`, `peers_unavailable` and `no_history`; plus `ageTagText`, `stockCountText`, `RISK_ROWS`, `ALLOCATION_TABS`. `fundFormat.ts`: `toneChipClass(tone)` gives the five tone tints for a chip or an icon disc (`pos`, `warn`, `neg`, `info`, `neu`), reusable for the Key Insights tone icons.
- `overview/holdingDialogs.tsx` (`StockDialog`, `SliceDialog`) and the `Modal` dialog row style (`<dl>` rows of muted label and bold value) are the pattern for `EvidenceDialog`, the manager popup and the bar and dot popups.
- `OverviewPage.tsx` has the final Overview layout. IF-B2 does not touch it.

## Contract points to settle before IF-B2 is prepared (the spec fixtures assume the first answer of each)
1. **Scatter peers a household holds:** RESOLVED in the contract for the front end (27 Oct, register C124): `held?: boolean` on each scatter point, optional-with-fallback (absent means no link); the backend run still has to add it, and the golden fixture will confirm.
2. **Reason codes:** `no_manager_data` (manager) and `no_history` (risk window under one year, rolling window longer than the history) are used by the spec fixtures and worded in `fundCopy.ts`; confirm with the real fixtures.
3. **Risk bands and the page words:** the band words and tones come from the API (`band`, `tone`); IF-B1 prints whatever string arrives and tints it by `tone`; confirm the exact band strings once the backend calibration run has fixed them (spec fixtures use `Low`, `Moderate`, `Fair`, `Good`, `Market-like`). Not an IF-B2 risk, but the scatter and the Insights facts quote the same figures.
4. **Insights `evidence` and `tone`:** the spec fixtures follow D14 (short tones `pos`, `warn`, `neg`, `info`, `neu`; evidence as `{label, value}` objects); the overlap fact's `id` is `overlap` and is the one the greyed row is keyed on.
5. **Allocation unclassified share:** DONE in IF-B1 on the assumption that `unclassified_pct` is the share the market-cap footnote prints and that the three market-cap slices sum to 100 without it (the fixture and the handoff agree); the golden fixture confirms.
