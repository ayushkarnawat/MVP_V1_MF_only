The plan's tasks 8 to 12 need about 18 implementation files, above the ~14 per packet. Prepare them as two packets, in this order (the second does not depend on the first except for `OverviewPage.tsx` and the shared copy, so they could also run in two worktrees if the owner wants speed):

- **IF-B2: the Insights tab and the parity step** (plan T10, T11, the Insights part of T12 and T13): 9 new files plus 1 route edit.

## Contract points to settle before IF-B1 and IF-B2 are prepared (the spec fixtures assume the first answer of each)
1. **Scatter peers a household holds:** plan T11 links a peer dot to its fund page "only when the household holds it", but `scatter` points carry `scheme_id`, `name`, `return_pct`, `volatility_pct`, `is_fund` only. Ask the backend run for a `held: boolean` on each point (or decide that no peer dot links). Default: add `held`.
2. **Reason codes:** the spec fixtures use `no_manager_data` for a missing manager and `no_history` for a risk window under one year (the handoff's stable list has no separate code for either). Confirm with the real fixtures.
3. **Risk bands and the page words:** the band words and tones come from the API (`band`, `tone`); confirm the exact band strings once the backend calibration run has fixed them (spec fixtures use `Low`, `Moderate`, `Fair`, `Good`, `Market-like`).
4. **Insights `evidence` and `tone`:** the spec fixtures follow D14 (short tones `pos`, `warn`, `neg`, `info`, `neu`; evidence as `{label, value}` objects); the overlap fact's `id` is `overlap` and is the one the greyed row is keyed on.
5. **Allocation unclassified share:** `unclassified_pct` is the share the footnote prints (plan A5 C); confirm that the three market-cap slices sum to 100 without it.
