# Antigravity print components: rules common to packets I7-AG-1 to I7-AG-4 (Batch I, M4)
**Written 2026-11-24.** The PDF prints the screens' own components; where a screen cannot print (a chart with no axes, a table that needs clicking, a donut that needs hovering) a **print-only component** replaces it. Antigravity builds these **presentational components**: they take data as props, draw it, and know nothing about hooks, routes or the server. Codex writes the small wrapper that calls the data hooks and maps them to your props (later, in the group tasks). The design source for every component is a **page of the approved sample report**: `Docs/orchestration/2026-11-13-batch-i-sample-report/full/fNN.png` (744 x 1053 px = A4, one pixel is 0.282 mm). ## The look rules (print root = light theme, 680 px wide, no animation)
- **Colours:** the app's tokens only (`var(--ui-text)`, `--ui-text-muted`, `--ui-divider`, `--ui-elevated`, `--ui-card`, `--pos`, `--neg`, `--warn-*`, `--c1..--c8`): the print root forces the light values, so tokens are safe. **No hex colour, no `rgb()`** in any file (a repo test checks `src/print/`). Series colours come from the same tokens the screen uses.
- **Type:** DM Sans for titles and Manrope for everything else are already set by the app; use the Tailwind sizes the screen cards use, **not** px values copied from the sample (the sample is a picture of the target look, the app's own scale is the means).
- **Cards:** the same card shell as the screen sections: `rounded-2xl border border-[var(--ui-divider)] bg-[var(--ui-elevated)] p-5`. A print component draws **the card's content**, with a title (a `<h4>` in the card's title style) as the sample shows.
- **Print rules:** no `<button>`, no `role="button"`, no `title`/`aria-label`-only content, no hover state, no animation or transition classes, no sticky or fixed elements, no scroll container, no `overflow-x-auto`. Tables: `table-fixed w-full`, header row in `<thead>` (repeats across pages: `display: table-header-group`), rows `break-inside-avoid` (Tailwind `break-inside-avoid`), numbers right-aligned with tabular figures.
- **Numbers and words:** **never retype logic or wording.** Money and percent through `formatRupees`, `formatCompactRupees`, `formatPercent`, `formatDate` from `frontend/src/lib/format.ts`; the compact lakh/crore style on chart axes as the screen's charts do (find how `LineAreaChart` formats its ticks and reuse the helper it uses). Decimals arrive as **strings**; do geometry with `Number(...)` only inside the drawing code and **never** use `parseFloat`, `.toFixed`, `Intl`, `console` or `any` (a repo test forbids them in `src/print/`). Dates: if you must print a date word, use `formatDataDate`/`formatDataDateTail` from `frontend/src/lib/dataDates.ts`; **never type "as on" or "as of"**.
- **Charts:** hand-drawn SVG (`viewBox`, `width="100%"`, no fixed pixel height attribute beyond the viewBox ratio), **no chart library** and no animation; text inside the SVG uses the muted token at a small size (the sample's axis labels are about 7 px at 744 px page width); gridlines `var(--ui-divider)`.

## Tests (Vitest, in your own folder; written first, shown failing, then passing; invented data)
Per component: the **content** (titles, rows, labels, legend items) renders from the props; **numbers equal what the formatters give for the props** (compute expected values in the test with the same formatters, not typed strings); **empty and one-item inputs** render without crashing and say something sensible (use the screen's own empty sentence if the packet names one); **no `<button>`, no `[title]`, no `role="button"`, no `aria-label` carrying content that is not also visible text**; no hex/`rgb(` in the component files (the repo guard covers it, but assert your own files too). Test file names: `<Component>.test.tsx` beside the component.
