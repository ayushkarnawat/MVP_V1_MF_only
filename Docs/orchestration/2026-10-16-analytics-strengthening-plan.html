7 · Knowing when an AMC has published

SP1SP2Medium impact

Two questions: has this AMC put its file out, and when do they usually? Neither is recorded anywhere today.

Timing, what we know

SEBI requires monthly portfolios on the AMC’s site by the 10th of the following month, which is presumably why SP2 alerts on days 10 and 20. Confirm against the current SEBI circular before relying on it. The SP2 spec says most AMCs publish the same day and Kotak about ten days later. Real per-AMC publishing days are not recorded.

Shared opportunity · one manual-upload admin screen

Both

Attribute 04 and SP2 have the same problem: AMCs obtainable only by a person downloading a file and running a command-line tool. A single screen would serve both, and would be one build instead of two.

Today

Proposed

Data: reuse first

Option A · no new table (recommended)

SP2’s queue already exists as disclosure_batches rows with status AWAITING_MANUAL_UPLOAD. SP1’s “due” list is computed from the registry plus the latest reference_period. The screen reads both and calls the existing import functions.

Option B · one audit table, only if you want a record of who uploaded what

Nothing stores who imported a file, when, or which file. Only failed files are archived. If that history matters, the single justified addition is below.

Blocker found while reading the code: there is no admin role. The API modules cover analytics, auth, CAS imports, dashboard, legal and scenarios; the user model was not found to carry an admin flag. An upload screen needs a way to say who may use it. Decide that before this item is sized: an admin flag on users, a separate internal-only route, or keeping the command-line tool and relying on alerts.
