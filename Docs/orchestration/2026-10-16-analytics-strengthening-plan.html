What the real files showed
  • One matcher rule rejects every ETF that has an “…FoF” twin: at least 20 funds across 8 AMCs.
  • “Formerly known as” notes block 16 Sundaram sheets and 8 Kotak funds.
  • Mixed units inside one sheet break 4 sheets (Wealth, ICICI ×2, Groww).
  • HDFC is rate-limited by the Internet Archive, and direct URLs cover only 83 of 153 funds.
  • On LeapSwitch, the job alerts reach nobody, and the jobs never exit with an error.
What needs a decision or an answer

  • Long-term factsheet source: keep manual, ask the AMCs, or buy data.
  • Manual imports: no new table, or one audit table?
  • Confirm “VCGE” is “WCGE”, and send the original WhiteOak and Edelweiss alert lines.
  • Server outputs from your manager (cron path, alert email, scheme master, AWS cluster).
What happens next, in order
  • Make alerts reach an inbox and exit with an error when AMCs fail.
  • Fix the matcher in order of yield: ETF rule, notes rule, units, small aliases.
  • Import the manual files for October.
  • Re-run the jobs before 31 Oct on LeapSwitch (clear the multi-sheet AMCs first).
  • Promote to AWS with the checklist, then run the same jobs there.

How safe is the fallback?
  • Of 974 real sheets, the current parser errors on exactly one (this one).
  • Value-derived weights match the reported percentages to within 0.05 points on 874 sheets, within 1 point on 57, and differ by more than 1 point on 42.
  • Those 42 are hedged, arbitrage and fund-of-fund sheets (Axis, Bajaj, Capitalmind, Old Bridge, quant, Jio and others) where holdings exceed net assets. So the value method is a fallback for the unit error only, never a replacement for the percent column.

  • The two DELETE statements are one transaction. Run the first `SELECT` with `ROLLBACK` to see what would go, and use `ROLLBACK` instead of `COMMIT` if the count looks wrong.
  • After a bad clear: restore the backup with sudo ./scripts/restore.sh on LeapSwitch, or the database snapshot on AWS, then re-run.
  • Between the clear and the re-run, those AMCs’ funds are missing from look-through. Do both in one sitting and run the recompute straight after.
  • Do not clear anything before the fixed code is on that server. Clearing first and running old code writes the same partial result again.
