Motion & interaction spec

TriggerBehaviourTiming
Hover a Market Cap / Category / AMC donut slice or legend rowSlice pops outward, others dim, center label swaps — identical mechanic to Overview's AMC donut--pop/--fast
Hover an Asset Class nested-ring legend rowMatching arcs in both rings dim the rest — no pop-out translate on this one (see Decided against)--fast
Click a Market Cap legend rowOpens the drill-down panel below with that bucket's top holdings; each holding expands to show which of your funds hold it and at what weight--fast

Decided against: radial pop-out hover on the Asset Class nested donut — with two rings at different radii sharing one hover target, a translate-based pop risks the outer ring's slice overlapping the inner ring's hole. Dim-only hover (both rings dim their non-matching arcs together, center label still swaps) reads just as clearly as "this is the hovered slice" without that risk — the single-ring donuts (Market Cap, Category, AMC) keep the full pop+dim mechanic since they don't share this problem. Also decided against building a live-reflowing drill-down for Category/AMC (unlike Market Cap) — design.md doesn't ask for one there, and AllocationSection.tsx's real component doesn't have one either.
Status: Allocation built per design.md §7.2 — all five breakdowns present (Asset Class, Market Cap promoted to first-class per Q6-A with every piece of CapAllocationSection carried over, Category, AMC, Fund Manager), zero new backend work. Ask-Mira coming-soon popup and the 1640px chrome width are shared verbatim with the Overview/Performance mockups (Round 4 pattern).

Round 5 (2026-10-24, pending sign-off): closed the "everything should be clickable" gap the owner called out — Asset Class's nested-donut legend and Category/AMC's combined-donut legend both already rendered a chevron (.l-chev, via the shared buildDonut helper) implying click-ability, but only hover was ever wired. Both now reuse Market Cap's existing .drill-panel/.drill-row click pattern: click a legend row, a panel below lists that slice's top contributing funds ("largest N of M", same non-exhaustive convention as Market Cap's own "largest 3 of 41 holdings" — no claim of full reconciliation). Category/AMC's drill re-renders on tab switch to default to the new top slice. The Fund Manager table's rows were fully static (cursor:default); each now expands on click to a detail row showing which scheme(s) that manager runs and their XIRR, reusing the canonical 4-sample-fund set shared with the Overview mockup (Kotak Multi Cap, JM Flexi Cap, HDFC Mid-Cap Opportunities, Parag Parikh Flexi Cap) rather than inventing unlisted figures. Every fund name introduced across the three new drill datasets (e.g. "HDFC Corporate Bond Fund", "HDFC Gold Fund", "Kotak Small Cap Fund") carries exactly one ₹ value used consistently everywhere it reappears on this page — checked by hand after the Overview Distributor-modal reconciliation bug this same round. Market Cap's legend itself stays hover-only, unchanged: it already has its own genuinely-wired drill-row/fund-list mechanic, so it wasn't part of the gap being closed here.

Round 6 (2026-10-24, reworking Round 5's own anti-pattern): the owner explicitly rejected Round 5's Asset Class/Category-AMC drill mechanic — clicking a legend row updated the panel below, but nothing visible tied the click to the update ("the user doesn't know what's updating... the user has no idea why I'm clicking this"). Fixed per the newly-written design.md §11.1 ("meaningful-click-or-hover, visible cause-effect" rule, now the cross-artifact philosophy for this whole sub-project): the clicked legend row now stays visibly selected (persistent left-accent border + open chevron, not just a hover-only tint that vanishes the moment the mouse leaves), the drill panel's title carries a dot colored to match the exact slice clicked, and the panel smooth-scrolls into view on click — so the row, the color, and the panel are tied together at a glance instead of the panel silently changing somewhere below. Fund Manager's row-expand (detail appears directly beneath the clicked row, same shape as Market Cap's drill-row) and Market Cap itself were already compliant with this rule and are unchanged.

Round 8 (2026-10-24, this round): the owner's three Allocation complaints, grounded against the real backend before writing any of this — cap_allocation.py (every market-cap bucket already computes up to 50 StockHoldingRows, not just the 3 this mockup showed, each with sector_raw, exposure_value/exposure_pct, and contributing_funds[] carrying BOTH fund_weight_pct and stock_weight_pct) and asset_allocation_lookthrough.py (confirmed the equity ring reuses that same per-stock computation, but Debt/Gold/Cash-like only ever get a scalar class total — no per-instrument data exists for them today). (1) Market Cap's legend click did nothing — Round 5's note above calling this "already genuinely wired" was wrong: the drill panel's expand/collapse worked, but it was 100% static HTML always labelled "Large Cap" regardless of which bucket was clicked, and buildDonut was never given an onClick callback for this card. Fixed: the legend now drives the panel like every other card (persistent selection, color-matched title, scroll-into-view), and each bucket's rows now carry sector + both contributing-fund weight percentages instead of just a fund name and one ₹ figure. "Other / Unclassified" intentionally shows no stock rows and says why — cap_allocation.py genuinely never computes rows for that bucket either, so a fabricated holdings list would have been less honest than the previous static panel, not more. (2) Asset Allocation "use everything the backend has" — Equity's drill now shows the same stock-level detail as Market Cap (same backend computation underneath) instead of a flat 3-fund list, with a cross-reference note pointing at the Market-Cap card below for the cap-wise split. Debt/Gold/ Cash-like stay fund-level (no richer data exists for them yet) but each fund row now shows its % of that asset class's own value, and a note flags the missing per-instrument breakdown as a real backend gap rather than papering over it. (3) Category/AMC "more interesting and unique" — this card's click mechanic already worked correctly, so this was a design-richness ask, not a bug: each contributing fund row now has a concentration bar and its % of that slice's value (both derived from the same ₹ figures already on this page, not new data), and the largest fund in the slice gets a marker. Also fixed a latent bug while touching this code: the old drill-row click handler ran once at page load via querySelectorAll, so it would have silently done nothing for rows re-rendered after a legend click, and would have mis-fired on Category/AMC's drill-rows (no data-expand attribute there, throwing on a null element) the moment those rows existed in the DOM — replaced with a delegated listener scoped to each panel. Fund Manager is untouched per the owner's explicit "looks good."
