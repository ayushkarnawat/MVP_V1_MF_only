## Decisions I am making for the open points Codex raised in H-8
1. **Where the state lives.** The container swaps `RequestCamsPath` for `WaitingForCasView` and back, which would lose a hook's state. So `useCamsChecklist(memberId)` reads and writes a **small module-level store** (`checklistStore.ts` in `features/import/checklist/`, `useSyncExternalStore`, keyed by `memberId`) holding `{ mode, step, ticks, camsLink, pipWindow }`; any component that calls the hook for the same member sees the same state. A second member has its own entry (starts at step 1, no ticks). The store is cleared by `startOver()` and by `markFileReady()` after the checklist closes.
2. **`CamsChecklist` props** (the H-8 tests go through the screens, so these are mine to set): `CamsChecklist({ api }: { api: CamsChecklistApi })` where `CamsChecklistApi = ReturnType<typeof useCamsChecklist>`. It renders the body only (no window chrome). A second component `CamsChecklistHost({ memberId })` (same folder) is mounted by `TwoPathImportContainer` for as long as the container is mounted: when `mode === "window"` it renders `<CamsChecklist/>` into the floating window's `document.body` with `createPortal` (so ticks update the same React state, no messages), when `mode === "panel"` it renders it in place on the screen (in the request and waiting views, above the main action, as a card), and when `mode === "closed"` and a saved state exists it renders the **"Your checklist closed"** card with **"Reopen checklist"** and **"Start over"**.
3. **"Continue without it"** is a link on the request screen, shown only when the API exists (`supported`), that makes **this request** behave as today (no floating window: await the request, `window.open(cams_url)`, move on). It is a per-request opt-out held in the screen's own state; it is not stored.
4. **`data-effect` values** (the repo's allowed list is `select, open, navigate, sort, switch, retry, expand, close`): "Open the CAMS form" `open`; "I have submitted the form" and "I have the file" `switch`; "Try again" `retry`; "Reopen checklist" `open`; "Start over" `retry`; "Continue without it" `close`. Every `<button` carries `data-clickable=""`.
5. **The early-return jump.** Today `TwoPathImportContainer` jumps to the upload screen on window focus (and at mount) when the resume marker is set. While the checklist is open (`mode` is `window` or `panel`, and step is not `ready`) **do not jump**; the jump (and the upload screen) happens when the user presses "I have the file" (`markFileReady()`), which also closes the floating window and clears the checklist state. With no checklist open, behaviour is exactly as today.
6. **Words** (nothing else new): the five items are the workbook's `PITEMS` (`Statement type: Detailed`, `Period: Specific Period, from 10 years ago to today`, `Folio listing: With zero balance folios`, `Email: the one registered with your funds`, `Password: 8 to 15 characters, a capital, a number, one of @ # $ * _. Remember it`; plain text, no bold markup needed), `n of 5 done`, the button `I have submitted the form` (disabled until all five are ticked), the step titles `Fill the CAMS form`, `Wait for the email`, `Your file is ready` (**new: used only as the heading of the third step; flag it**), `Open the CAMS form` with `Getting your link ready` while preparing, `Try again`, `I have the file`, `Your checklist closed`, `Reopen checklist`, `Start over`, `Continue without it`, and the line `A small checklist will float over the CAMS page` (shown above the green button where supported).
