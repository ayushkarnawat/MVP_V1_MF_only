## The contract (fixed here; do not rename or reshape)
```python
# category_ranking.py
PeriodReturns = tuple[Decimal | None, Decimal | None, Decimal | None, Decimal | None]   # (r1, r3, r5, blended)
class PeerReturns(NamedTuple):
    peers: CategoryPeers                        # the existing type from get_category_peers
    detailed: dict[uuid.UUID, PeriodReturns]    # every active, same-category, same-plan peer with end NAV and at least one period return; short-history peers INCLUDED
async def load_peer_returns(db: Session, scheme: Scheme, today: date) -> PeerReturns
def period_members(detailed: Mapping[uuid.UUID, PeriodReturns], period: Literal["1Y", "3Y", "5Y"]) -> dict[uuid.UUID, Decimal]   # funds whose return for that period is not None
```
**Rule.** `load_peer_returns` is the **one** place that decides pool membership (active, canonical category, plan match, end NAV present) and calls `_category_returns_detailed(..., include_short_history=True)`. `load_category_pool` builds on it and applies the average's own index rule (`is_index_fund(peer) == held_is_index`); `load_ranking_pools` builds on it and applies its own (`not _is_index(s)`) **exactly as today** (so the rank pools do not change for any existing fixture). `category_period_weighted_averages` and `category_period_averages` build **each period's average over `period_members(detailed, period)`** (so a fund joins the 1Y average if it has a 1Y return, the 3Y average if it has a 3Y return, the 5Y average if it has a 5Y return); the size weighting and `funds_without_size` logic per period are unchanged. `_legacy_average_from_periods` still returns None when the 3y average is None (the blended single figure keeps its 3-year rule). `CategoryPool`, `RankingPools`, `CategoryAverage` and every public signature keep their shape. One comment where the floor was: "Pools are per period so the average and the rank always count the same funds (owner, 25 Nov 2026, QA-12 A); the 3-year rule survives only in the blended figure."
**Not changed:** any API route or response model, the card wording, `thin_category`'s meaning, a held fund under 3 years still reads "Not enough history" (the `own = None` rule), the stored-results tables (they are rebuilt after deploy, not here).
