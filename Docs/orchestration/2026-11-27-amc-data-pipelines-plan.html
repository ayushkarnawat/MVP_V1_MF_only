0 · Bottom line

Most of the monthly chaos is not the downloading. It is everything around it. Today each by-hand file is found on a site, renamed, copied to the VM with scp, imported with a long ssh … docker compose run … command with exactly the right house name and flags, and the result is pasted back into chat. There is no dry run, no undo, no list of what is still due, and no record of what was done. That repeats for about 25 house imports a month (11 disclosure houses, up to 14 factsheet houses).

My recommendation, in order:

  1. Status check (S): done 27 Nov. October holdings cover 82% of fund money but only 44% of live series, unchanged since 18 Nov; 15 of 51 houses have nothing for October and no October by-hand import was done. Every testable cause from 19 Nov is confirmed, and three new problems were found (Groww now refuses us, Taurus never fetched, matured funds still live). Section 4.
  2. Make failure visible, then fix the bugs (H1–H3, then F). One outcome row per fund house per run, a daily digest email, non-zero exits. Then the eight code fixes, ordered by funds recovered. Hard deadline: FX-L1 (the weekend date rule) must be live before 1 Feb 2027, because 31 Jan 2027 is a Sunday and Franklin's files will be missed again.
  3. Replace the CLI routine with an Ops console (A1). Drop files on a page; the house and month are detected from the file; a dry run shows what would be written, compared with last month; one click commits; one click undoes. Plus a due list, so nothing is forgotten. This removes most of the chaos on its own.
  4. Cut the clicks with a Collector browser extension (A2). A person still opens each AMC page in their own browser (so we never get around a site's block), but the extension picks up each download, tags it and sends it to the Ops console. The monthly routine becomes "open the due list, click through, review, commit": about 30–40 minutes instead of an afternoon.
  5. Work towards real automation in parallel (A5–A7): ask the blocked houses to allow our fixed server address, try an email inbox that receives AMC mailings (Amazon SES can receive mail in Mumbai), and get quotes from data vendors. Each one, when it works for a house, takes that house off the manual list.

What I do not recommend: an unattended AI agent that drives a browser from a home or office connection to download files from sites that refuse our server. It would work technically, but it is exactly the "access-control workaround" the project ruled out in Run 7 (10 Oct), the sites' terms usually forbid automated access, and it fails silently when a page changes. A supervised pilot is offered as an option in Q12, so it is your call.

7.4 How detection works (so nobody types a house name again)

  • Pipeline: PDF → factsheet; .xls/.xlsx/.zip → disclosure (the same sniffing sniff_workbook_format already does).
  • House: match the file's text (title block, sheet names, the AMC name printed on every disclosure and factsheet) against registry keys and aliases; for the Collector and email, the page or sender domain is a second signal. Two signals must agree, or the console asks the person to pick.

A2 in depth · The Collector extension

Added 28 Nov at your request. What A2 is, exactly what we build, what changes in the database, backend and front end, where it runs, how it works step by step, how much of today's by-hand work it covers, and why it is the right tool for the houses no server can reach. A3 follows in the next section.

A2 in one paragraph. The Collector is a small Chrome extension that only Unifolio staff install (never app users). It opens as a panel on the right of the browser and shows this month's list of files that a person must download. A staff member clicks Open page, the fund house's own website opens, and they click that site's own Download button as anyone would. From that moment the Collector does the rest: it picks up the finished download, checks it came from the right fund house, sends it to our server, and shows the dry run (what would be written, next to last month). If everything agrees it commits, then moves to the next house. The person does two clicks per file. The Collector does the other six steps that make the monthly round chaotic today: renaming, copying to the VM, typing the import command with the exact house name, reading the counts, judging them, and keeping track.

A2.1 What A2 stands on: A1 and H1, in plain words

A1 · Intake and the Ops console. One place on our server where every file arrives, from any route: drag-and-drop on the Ops console, the Collector, the email inbox, or a feed. For each file it stores it once (by its sha-256), reads the house, pipeline and date from inside the file, and runs a dry run: our existing parser and matcher, writing into a recorder instead of the database. Then it commits through the existing writers and keeps a one-click undo. A2 is only a faster way into A1. Without A1 the Collector would have nowhere to send files.

H1 · One outcome per fund house per run. A new table, pipeline_run_outcomes, gets one row each time a job or an intake touches a house. Each row has a reason from a fixed list: WRITTEN, BLOCKED, WRONG_DATE, AWAITING_FILE, NOT_PUBLISHED and the rest. That is what builds the "due by hand" list the Collector shows. A house that refused our server this morning (BLOCKED) appears on the list automatically. A committed Collector file writes WRITTEN with source = collector, and the house leaves the list.

The mechanics behind each step (Chrome's own extension APIs; the two marked "spike" are proven first):

  1. Connect. The app signs requests with a bearer token stored in the existing sessions table, which already has a device_info column. "Connect this browser" creates one more session row for the staff member, labelled collector: <browser name>. The console page passes its token straight to the extension (Chrome's externally_connectable, allowed only for the console's address), and the extension keeps it in its own storage. Revoking deletes that row. A Collector session can call only /ops/collector/* and /ops/intake/{id}; every other route refuses it.
  2. List. GET /ops/collector/plan?cycle= returns the due items (from H1 outcomes and the by-hand registry): house, pipeline, period, page link, the house's allowed web addresses, the hint, and status.
  3. Open page. The panel opens the link in the current tab and marks that house active. Nothing is fetched yet.
  4. Capture. Chrome's downloads API tells the extension when a download finishes, with its file name, size, address and the page it came from. If that address is not one of the active house's addresses, the extension ignores the download: it never reads or sends it.
  5. Read the file spike. The download API gives the file's name and size, not its contents. The first time, the panel asks the person to choose their Downloads folder (Chrome's File System Access, shown once). After that it reads the finished file directly and checks the size matches. That is the same file the person just downloaded, with no second request to the fund house. Fallback if Chrome does not allow this from a side panel: the extension downloads the same address once more from the same browser (same sign-in, same address). Last resort: drag the file onto the panel.
  6. Send. The panel checks the type (xls, xlsx, zip, pdf) and size (≤ 25 MB) and computes the sha-256 in the browser. It then posts the file with the page address, download address, original name and the active house as a hint. A file already seen (same sha-256) is reported as a duplicate and not stored twice.
  7. Detect and dry run (A1, on our server). House, pipeline and date are read from the file's own text. The house is checked against the Collector's hint: two signals must agree, otherwise it waits for a person to choose. The dry run runs on the worker container and the panel polls /ops/intake/{id}.
  8. Commit. If the auto-commit rules pass (house and date certain, every sheet parsed, matched ≥ 90% of last month, no new sum-check failures), it commits and the panel says so. Otherwise the panel shows "Review in console". Commit writes through the existing writers, tags the rows with the intake id (so undo is exact), and writes an H1 outcome with source = collector. The house leaves the list and the panel offers the next one.

A2.5 What the extension can and cannot see

  • Permissions it asks for: side panel, downloads, its own storage, and our API's address. If the fallback re-fetch is needed, also the fund houses' addresses (a fixed list).

  • The download list is the sensitive part: Chrome's download permission shows the names of all downloads in that browser profile. The code ignores anything not from the active house's site, and the rule is to use a separate Chrome profile just for this work, so there is nothing personal in it.
  • It never acts on a site by itself. Every request to a fund house is the person's own click. That is why A2 stays inside the Run 7 rule even for houses that refuse our server: a person browsing a public page and saving a file is exactly what those sites allow.

7b.2 What Claude can do here, from the platform docs (checked today)

  • The browser-use and computer-use tools run in a browser or desktop we host. The model decides what to click; the requests leave from our machine.   • The web fetch tool runs on Anthropic's servers. Using it to reach a site that refuses us would only move the request to someone else's address, which is the same workaround by another route. It is also unnecessary for sites that let us in. The plan does not use it for AMC sites; our agents get a fetch tool we run ourselves, limited to each house's own domains.
  • PDFs: Claude reads a PDF as text plus a picture of each page (about 1,500–3,000 text tokens and up to 1,568 image tokens a page; up to 600 pages a request with the 1M context). So a factsheet layout our code cannot read can be read by an agent into a fixed structure, then checked by our own rules. Spreadsheets are not accepted directly; our existing parser already handles them.
  • Prices (per million tokens): Sonnet 5.5 $2 in / $10 out, Haiku 5.5 $0.10 / $0.50 (prompts up to 100k), Batch API half price. Costs in 7b.6.

7b.4 Guardrails (what the agents may never do)

  • Stop at a refusal. HTTP 401, 403, 406 or 429, a challenge page or a CAPTCHA ends the attempt for that house as BLOCKED. There is no retry with another identity, address, header set or service, and no CAPTCHA solving.
  • Honest identity. The same browser user agent the job already sends (as today), or headless Chromium's own; robots.txt respected; one request every 2–3 seconds per house; daily runs only.
  • Own domains only. Each house's agent tools accept only that house's registered domains (plus its file CDN). No search engines, no third-party mirrors, no Anthropic web fetch.
  • No logins, keys or forms except public filters the site's own download page offers (month and year selectors).
  • Never writes on its own judgement. What an agent finds goes through the same dry run and rule-based auto-commit gate as a person's upload. Anything outside the rules waits in the Ops queue.
  • Never edits code or the registry. AG-5 proposes; people review.
  • Budget and kill switch. A hard monthly limit; past it the agents stop and the digest says so.

12 · Risks and how the plan handles them

  • FX-L1 creates two live batches for one month if a house later re-dates 30 Oct to 31 Oct. Covered by a fixture and by comparing by calendar month everywhere.
  • Auto-detection picks the wrong house. Two signals must agree; otherwise the person chooses. Commit is never automatic without certainty (Q19), and undo exists.
  • Undo after users already saw the data. Holdings consumers read the newest WRITTEN batch, so undo simply falls back to the previous month's batch; analytics recompute runs nightly.
  • Outcome noise floods the digest. The digest shows changes since yesterday, not the full table.
  • Extension distribution. An unlisted Chrome Web Store item or developer-mode install for two or three people; token revocable from the console.
  • Email intake links are login or tracking links. Only links to registered AMC domains are followed, plain GET, no credentials.
  • Vendor licence forbids showing raw holdings to users. Read before signing; derived numbers may still be allowed.
  • December runs on today's code, with today's blind spots (status check, 27 Nov): LIC will again keep one workbook of two, Samco and Zerodha write nothing, and Groww may now be refused. 30 Nov is a Monday, so the date bug does not bite. Check with the same script after 20 Dec.
