## Build (new files unless marked)
1. **`frontend/src/lib/printMode.tsx`** (shared lib, so components can read it without importing `print/`): `PrintModeValue = { folios: "full" | "masked" | "none"; dataDates: boolean }`; `PrintModeProvider({ value, children })`; `usePrintMode(): PrintModeValue | null` (**null whenever not printing**: every existing screen must behave exactly as today, and every existing test must pass untouched).
2. **Print runtime** `frontend/src/print/printRuntime.ts`: `installPrintRuntime()` (called once by the route): sets `data-theme="light"` on `<html>` and removes any `dark` class, **overriding the dark `prefers-color-scheme` rules** (the app's dark rules are guarded by `:root:not([data-theme="light"])`, so the attribute is enough: verify with a test that reads `getComputedStyle` of a token), injects one `<style data-print-runtime>` with `*,*::before,*::after { animation: none !important; transition: none !important; scroll-behavior: auto !important; }`, `html, body { background: #fff }` (**the only hex in the folder: put it in `print-runtime.css` imported by the route**, and the guard test below allows that file), and marks `<html data-print="true">`.
3. **Memory-only token** (`frontend/src/features/auth/session.ts`, modify): add `setTokenOverride(token: string | null): void` and make `getToken()` return the override first, then `localStorage` as today. The override lives in a module variable only (**never** `localStorage`, `sessionStorage`, cookies or the URL). Existing behaviour and tests unchanged when no override is set.
4. **The fragment** `frontend/src/print/printFragment.ts`: `parsePrintFragment(hash: string): { pass: string; options: PrintOptions } | null` and `clearFragment(): void`. The route is opened as `/print/report#pass=<token>&opts=<base64url(JSON)>` (the fragment is never sent to a server). `PrintOptions = { scope: "family" | string /* member id */; sectionIds: string[]; cover: boolean; dataDates: boolean; showFolios: "full" | "masked" | "none"; jobId: string }`. Validation: unknown keys ignored; `sectionIds` must all be known ids (see 6) else the route shows an error marker; pass length capped (1024). `clearFragment()` calls `history.replaceState(null, "", location.pathname)`.
5. **The route** `frontend/src/print/PrintReport.tsx` (default export or named `PrintReport`) and the branch in `frontend/src/main.tsx` (**add** `/print/report` beside the existing `/print/analytics` check; touch nothing else there): on mount it parses the fragment, calls `setTokenOverride(pass)`, clears the fragment, calls `installPrintRuntime()`, and renders, **outside the app shell** (no AppLayout, sidebar, top bar, section rail, search box, date strip, Mira dialog): `PrintModeProvider` + a scope provider + the requested sections in the order given, each wrapped in `<section data-print-section="<id>">`. **Scope provider:** the sections read `useScope()` (`viewMode`, `memberId`, `members`, `scopeKey`); look at `frontend/src/shell/scope/ScopeProvider.tsx` and reuse it if it can run under the pass (it loads the household members), otherwise write a minimal provider that sets `viewMode: scope === "family" ? "aggregate" : "member"`, `memberId`, and loads the member list through the **same API function** the shell uses; **report which route that call hits** (the backend allow-list needs it). No section may ever call a write route (a test asserts only GET requests are made).
6. **Section registry** `frontend/src/print/sectionRegistry.ts`: `PRINT_SECTIONS: Record<string, { tab: MfTabId; title: string; render: () => ReactNode }>`, **one entry for every id in `SECTION_LISTS`** (`frontend/src/lib/pageSections.ts`), titles taken from that list. Every entry starts as `render: () => <PrintPlaceholder id title />` where `PrintPlaceholder` shows the section title and the plain line **`This section is not in the PDF yet.`** (new words, internal and temporary: flag it) and reports itself settled. A test asserts **every `SECTION_LISTS` id has an entry** and no extra ids exist, so a future section added to the list without a print entry fails the build. Later tasks replace entries one group at a time.
7. **Ready marker and waiting** `frontend/src/print/usePrintSettled.ts` and `PrintReadyGate`: each section wrapper registers `usePrintSettled(id, settled)`; the route sets `document.documentElement.dataset.printReady = "true"` only when **every requested section has settled** (data loaded, or the section's own failed state showing), **and** `document.fonts.ready` has resolved, **and** every `<img>` in the document is complete (or errored: logos fall back to initials), **and** two animation frames have passed. A failed or empty section **prints its own failure text in place** (and the report still becomes ready); a total timeout of **60 s** sets `data-print-error="true"` instead (never both). The same pattern as the old page (`PrintAnalyticsView.tsx` lines 41 to 54).
8. **`SectionCard` in print mode** (`frontend/src/features/mutual-funds/common/SectionCard.tsx`, modify): when `usePrintMode()` is non-null: **no `InfoMark`**, **no Retry button** (a failed section shows its failure sentence only), no skeleton shimmer class (the route waits, but never print a pulsing placeholder), no `title`-only content added. Outside print mode: byte-identical behaviour (existing tests untouched).
9. **`InfoMark`** (find where it is defined: used by `SectionCard.tsx` and the section files; `frontend/src/components/info/InfoPopover.tsx` has the popover): render `null` in print mode.
10. **`FolioNumber`** (`frontend/src/components/mf/FolioNumber.tsx`, modify): in print mode ignore the eye-icon setting (`frontend/src/lib/folioVisibility.ts`) and follow `PrintModeValue.folios`: `"full"` the full number, `"masked"` `maskFolio(value)`, `"none"` render nothing; **no toggle button in print mode**. PAN is never rendered by any component (assert nothing new introduces it).
11. **Charts without animation** (`frontend/src/components/ui/charts/use-mount-progress.ts` and `animation.ts`; modify): when `usePrintMode()` is non-null the mount progress is **1 immediately** (no 1.1 s tween) and clip-reveal transitions have duration 0; outside print mode unchanged. The hand-made donuts (`mutual-funds/common/charts.tsx`) have only CSS transitions, already disabled by the runtime stylesheet.
12. **Fixed width**: the route's root `<div>` is `width: 680px; margin: 0 auto` (about 180 mm at 96 dpi) with `data-print-root`; no section may rely on the window width (the renderer sets the viewport to 680 px wide: note this in the report).
13. **Bundled fonts**: DM Sans 700 and Manrope are already bundled by the Antigravity template lane (`frontend/src/print/fonts/`, on another branch); **do not copy them in this task**. Instead make the route load fonts through a `print-fonts` import that this branch provides as a **stub** (an empty `print-fonts.css`) with the comment "replaced by the template lane's file at merge"; the test `fonts load from the bundle, not Google` runs against whatever `print-fonts.css` holds (no URL to another host).
