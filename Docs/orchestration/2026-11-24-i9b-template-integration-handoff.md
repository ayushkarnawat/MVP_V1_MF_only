## The report page, in order
`PrintReport` (inside `PrintTemplate`, which applies the tokens, fonts and page rules) renders, for the parsed options:
1. **`Cover`** only when `options.cover` is true. Props from `options.meta` and the data (below). The cover is its own page and has no header or footer (the template's named page does that).
2. **`Contents`** when `options.cover` is true (decision: the contents belong to the cover set; with the cover off the report is the bare sections). `entries`: one per requested section, in the requested order, `{ tab: <tab label>, title: <the section's title from the registry>, page: <number or null> }`, followed by the last entry `{ tab: "Notes", title: "Notes", page }`. **Page numbers:** `options.pages` (optional `Record<string, number>`, keys are section ids plus `"notes"`) supplies them; absent means `page: null` (nothing printed at the right). `pages` is also settable after load through the browser hook below.
3. For each **tab** that has at least one requested section, in the tab order of `SECTION_LISTS`: **`TabHeading`** with the tab's label (Overview, Performance, Allocation, Holdings, Transactions, Overlap, Other Analytics: use `TAB_DEFS[...].label` from `features/mutual-funds/frame/MutualFundsFrame.tsx` or the same names), then that tab's requested sections in **the tab's own order** (not the order in `sectionIds`; the dialog sends them in list order anyway), each wrapped as today in `<section data-print-section="<id>">`. **Do not use `SectionHeading`**: the section components already draw their own card titles, so a second heading would duplicate it.
4. **`NotesPage`** last, always (with or without the cover) with `priceDate` and `marketCapDate`.
5. **`RunningHeader` and `RunningFooter`** rendered once (they set the root custom properties the page margin boxes read): `scopeName` for the header = for a family report with a holder `<holderName> and family`, for a family report without one `meta.scopeName` (the back end sends `"Your family"`), for a member report `meta.scopeName`; footer `generatedOn` = today in the format the cover uses (see below), `priceNote` = the prices data date through `formatDataDate("prices", iso)` (or `null` when the date is unknown or `options.dataDates` is false).

## Data the template needs (no new endpoint; the same hooks the sections use)
- **Prices date and holdings date:** the latest price date the sections already use (see how the Performance history wrapper computes its `asOf` from the holdings hook, and the analytics `asset_allocation` payload's `nav_as_of` / `holdings_as_of`). Put the lookup in one hook `useReportDates()` in `frontend/src/print/` returning `{ pricesIso, holdingsIso, marketCapIso }` (any may be null) from the **same stores the sections already fill** (so it causes no extra request: it reads the cached analytics/holdings results; it must **not** fetch on its own). While they are not available the cover's date columns are simply omitted and the footer note is null; the ready gate already waits for the sections, which load the same data.
- **Counts for the cover:** `fundCount` = distinct funds and `folioCount` = distinct folios in the holdings the screen shows for the scope (from the holdings hook the sections use); `memberCount` from `meta`.
- **A helper in `frontend/src/lib/dataDates.ts` (additive, with tests in `dataDates.test.ts`):** `formatDataDateParts(kind, iso): { label: string; value: string } | null` returning the label (`Prices as on`, `Holdings as on`, ...) and the date text separately (`5 Oct 2026`, `September 2026`) from **the same tables** `formatDataDate` uses, so the cover's two columns read exactly as the screens do; `null` for an invalid date. Cover `dataDates` = the prices and holdings parts that exist.
- **`generatedOn`:** today as `5 Oct 2026` style via `formatDate(new Date().toISOString())` from `lib/format` (check its output form; if it differs from the cover's `17 Nov 2026`, add a small formatter in `print/` and say so).
- **`scopeLabel`:** `Family Combined, full report` (family scope, every section requested), `<member name>, full report` (member scope, every section), or `<scope name>, <n> sections` when only some sections were requested (**new wording** `<n> sections`: flag it). "Every section requested" means `sectionIds` equals the full list of registry ids.
- **`Cover` props:** `holderName: meta.holderName`, `scope: { kind: "family" }` or `{ kind: "member", memberName: meta.scopeName }`, `memberCount: meta.memberCount`, `fundCount`, `folioCount`, `generatedOn`, `scopeLabel`, `dataDates`. (The cover component already builds "Prepared for", "Your family" and the sub line.)
- **Notes dates:** `priceDate = pricesIso`, `marketCapDate = marketCapIso`.

## The page-number hook and the section markers (so the back end can fill the contents in a second pass)
1. **A marker in every section wrapper:** inside each `<section data-print-section="<id>">` put, as the first child, `<p data-print-marker aria-hidden="true">[[sec:<id>]]</p>` styled so it prints but is invisible (`font-size: 1px; line-height: 1px; color: transparent; margin: 0; height: 1px; overflow: hidden;` through a class in a print stylesheet, no hex), and the same `[[sec:notes]]` marker as the first child of the notes page's wrapper. The back end finds the page of each marker by extracting the PDF's text.
2. **`window.__unifolioSetPrintPages(map: Record<string, number>)`**: installed by `PrintReport` once mounted; it sets the `pages` state (merging with `options.pages`), so the contents re-render with the numbers **without reloading or refetching**; it returns after the next animation frame (a promise). The back end calls it between its two prints.
3. While `pages` is empty the contents entries have `page: null`.
