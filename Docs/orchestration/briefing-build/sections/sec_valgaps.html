Item 7 methodology gaps, and how each one is covered

The earlier methodology listed what was unverified. Each gap now has a cause, a way to cover it, and the check that proves it. "Where" says whether it needs the VM.

GapWhy it mattersHow we cover itCheck (where)
1. Factsheet coverage was unknownDecides how many funds show a printed figure.Now known: 5 houses print per-scheme P/E and P/B (Invesco, ITI, Kotak by hand; UTI, ABSL automatic), confirmed on the VM's current files for the automatic houses on 30 Oct. The rest use the computed path.Repeat after the 10 Nov job; the monthly check
2. Forward versus trailingInvesco's P/E is forward (FY27E); the others trailing or unstated. A portfolio line cannot mix them silently.Every stored value keeps its basis. The fund table shows the printed value with 'fwd' and a plain-words hover note (Q2). The portfolio line uses one basis (D39).Unit tests on the resolver
3. Averaging method differs by houseUTI and Invesco state a harmonic mean; Kotak and ITI do not say.Store the method (harmonic, weighted average, not stated). The label says 'method not stated' where true. Our own computation stays harmonic (D17, Q6) with the plain-words reason.Parser tests per house
4. Label and value are separate textKotak, ITI and UTI would be misread by a line-by-line parser.Positional extraction (word boxes) for those three, as already done for Axis, ICICI, Franklin, LIC and Taurus.Fixture tests from saved snippets
5. A figure could be inside a pictureA house could print it as an image.The monthly scan flags image-only pages. If any appear, OCR for that house only. None found in 94 PDFs so far.S3 (VM)
6. A parse error reaching the screenA misread table could show P/E 0 or 4,000.Sanity range (P/E 3 to 200, P/B 0.2 to 40): outside is treated as not found and logged. This catches impossible values only; a fund house's own mistake would be shown (your decision).Unit tests
7. BSE's own data is blockedBSE-only stocks have no P/E from NSE.The BSE price file (works from the VM, verified 30 Oct) identifies and prices them. Their ratios use the same labelled fallbacks as P/B today (Yahoo, screener.in) and are marked unofficial; below the 70% coverage floor a fund shows 'Not enough data'. The BSE data API answers 403 from the VM, so BSE's own ratios are not planned.S5 done 30 Oct
8. How many BSE-only stocks funds really holdThe scale decides if Phase B is worth building.Counted on staging, 30 Oct: 96 equity stocks held by funds have no NSE symbol (BSE-only candidates) and 278 have no stored P/E (some are loss-making, some BSE-only). Small enough that Phase B is a one-day task.S7 done 30 Oct
9. Which NSE column is right (P/E or Adjusted P/E)The NSE file has two P/E columns; only the first is read.Read NSE's definition of the adjusted column and compare both against a known stock; document the choice.Desk check plus S4 (VM)
10. P/B depends on Yahoo and screener.inUnofficial sources can break or change.Phase C: book value from the latest year-end or half-year filing (equity attributable to owners divided by shares in issue, times the day's price). One stated basis. Yahoo and screener.in stay only as labelled fallbacks.S6 (VM)
11. Banks, insurers and finance companiesThey file in different formats; one formula may not fit.Test one of each in the spike. If the formula does not apply, those stocks keep the fallback and are named in the excluded list.S6 (VM)
12. The September half-year filingThe June quarterly filing has no balance sheet; only year-end and half-year do.Spike: open the September XBRL file and confirm it holds equity and shares. Book value is up to 6 to 12 months old, and its date is shown.S6 (VM)
13. Request volume and pacingAbout two requests per stock per new filing; a few thousand stocks.Refresh only when a new filing appears; pace like the existing stock job (0.3 s). Estimate the total in the spike before building.S6 (VM)
14. The staging VM's addressExchanges block some cloud addresses; tests so far were from a developer machine.Tested from the VM on 30 Oct: the NSE P/E file, the security master, niftyindices (total-return and price endpoints), AMFI and the BSE bhavcopy all answered 200; the BSE API answered 403 as expected. The NSE Integrated Filing endpoint (S6) is not tested yet. If a source is blocked later, that phase stops and the fallback stays.S4, S5 done; S6 open
15. Terms of useAutomated download of exchange data may be restricted; index levels may need a licence.Written check before scaling (S10). Show derived returns only, not raw index levels.S10 (a person)
16. FreshnessA printed value is a month-end figure.Use the latest factsheet value only if it is at most about 75 days old on the NAV date (Q1); the date is shown beside every number. Direct and Regular plans of one scheme share the printed value.Unit tests
17. Layout changes and skipped monthsA house changes its factsheet and the parser silently finds nothing.Parser-health alerts and the monthly check above; the missed-month alert for the 10 hand-import houses (Priority 1) is part of Run 2.Monthly check
18. Overseas and loss-making holdingsNo P/E exists for them; they would lower coverage.Overseas holdings are counted separately and not called missing. Loss-making stocks are excluded from the harmonic mean and named, as today.Unit tests
19. Factsheet month versus NAV dateThe August factsheet's figures are used in October.The as-on date comes from the factsheet's own caption and is shown. Older than the 75-day rule falls back to computing.Unit tests
