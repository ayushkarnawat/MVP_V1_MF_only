Shell Design Workbook

Design system, mockups and open questions for the navigation shell (left sidebar, top bar, layouts), prepared 23 Oct 2026 from the written shell documents. Nothing is built. Claims are marked verified, estimate or unverified. Answer the cards, then copy your answers at the bottom.

Source of truth: Web app UI mockups MFs.pdf for structure and Unifolio Colour Palette.pdf for colour and type. Where they differ, the newer palette wins and the difference is a question (SP1). I edit no existing document without your yes.
Scope: desktop only. Mobile and existing screens are untouched. The search box keeps its place; its behaviour is on hold (L46).

One-minute summary

  • Done: nine shell documents are written (list below). They follow the frozen decisions from the left-panel planning and use the new palette for every colour.

6. Import and Coming soon pages

Frozen decisions these documents rely on

From the left-panel planning (22 to 23 Oct) and your answers. Tell me if I got any wrong.

What happens next

  1. You answer the cards. I update the documents to match and record the answers as decisions.
  2. Implementation plans are written (the owner's step 11), one plan for the shell split into PR 1 and PR 2.
  3. No product code, install or commit until you say go. Planning effort for the sidebar part was estimated earlier at about 7 to 8 developer-days (estimate), before PR 2's switch-over.

Risks to keep in view

  • Two colour sets. The shell follows the palette while existing screens keep today's tokens, so some areas look slightly different until a global move (SP2).
  • Landing on a placeholder. If PR 2 ships before Home, users land on Coming soon (SF1).
  • Features that become unreachable. History and Analytics have no link until the Mutual Funds menu exists (SF2); the global Add data button is gone (SF3).
  • Moving scope logic out of MainDashboardFlow can change member defaults, banners and the import notice. Port the tests first.
  • Faint disabled rows. The palette's disabled grey is about 1.7:1 on the page background (SP4).

To verify before building

  • A MemoryRouter test with a React.lazy page settles with findBy queries under Vitest.
  • That import.meta.glob works the same under Vitest (it uses Vite's transform).
  • Whether DashboardView's and AnalyticsView's add-data entries are always visible (SF3).
  • That the 20 Node tags in CI and deploy.sh resolve to 20.19 or newer, and where AWS staging builds the frontend.
  • The dark-mode values the palette does not give (muted icon, disabled text, selected tint).
  • That a sidebar-width of about 224 px suits the real pages (an estimate from the mockup).
