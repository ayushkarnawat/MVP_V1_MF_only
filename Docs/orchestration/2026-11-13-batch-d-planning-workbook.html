The root cause (found in code, tested in a browser, confirmed on staging)

  1. The benchmark line and the text line under the portfolio value are painted with the colour variable --home-bench (features/home/sections/WealthCard.tsx, lines 260 and 344).
  2. --home-bench is defined in exactly one place: features/home/home-tokens.css (set to the palette blue).
  3. Nothing imports that file. src/index.css imports tokens.css and palette-tokens.css but not home-tokens.css, in the deployed commit 07a3057c and in the current branch. The only reference to the file anywhere is its own test, and the file was never imported at any point in the history (the one commit that mentions it added that test).
  4. So at runtime the variable does not exist. I tested what a browser does with that: an SVG line whose stroke is an undefined variable gets stroke = none (invisible), while a line using a defined variable such as --c1 draws normally. The text line falls back to the surrounding text colour.
  5. The existing test checks that the file defines the tokens, so it passes while the app never loads them. That is why nobody caught it.
  6. Confirmed on staging (13 Nov): on the live Home page, getComputedStyle(document.documentElement).getPropertyValue('--home-bench') in the browser Console returned an empty string, so the variable is not defined at runtime.
