## Two surfaces, two rules
1. **The floating window (W1, W2, W3) is always light.** It is a separate browser window whose document gets copies of our stylesheets; the app's own tokens there would follow the *operating system's* dark setting through `prefers-color-scheme`. So **do not use the app's `--color-*` tokens inside the window.** Wrap the body in a root class `cams-checklist-window` and define everything it needs as fixed light values in `checklist-tokens.css` under that class (`--ccw-*` custom properties). The window's content area is **320 px wide**; it must also look right if the user drags it smaller or larger (a minimum of 260 px works, the content wraps, nothing overflows horizontally); it scrolls vertically when taller than the window.
2. **The in-page pieces (panel FB, closed card RO, the two green notes S2 and UP) live in the app**: they use light/dark pairs (`--ccp-*`) defined in the same CSS file, light on `:root`, dark under the app's dark selectors (copy the exact selectors that `frontend/src/styles/tokens.css` uses for dark mode, so they switch with the app's theme toggle).
