3. The calculation and the Excel in depth (item 9)

Prove the numbers are right, fix anything that is not, and build the detailed Excel for stakeholders. This work moved here from Batch E. On 17 Nov you also dropped the on-screen “i” for the category average: the Excel is the only explanation, so it has to be complete.

What the user sees today (read in code)

Made-up fund; the three rows use your three examples. A filled dot is the fund, a hollow dot is the category average; green means ahead, red means behind (from the card’s own legend line). The sentence under the rows says how many funds the average covers for each period.

What the card shows after this plan

Card

The only visible change is one short line under the existing sentence. The card has no “i” and no date (both decided 17 Nov); everything else is explained in the Excel.

How the average is calculated (read in code)

  1. Pool: the same pool as the rank (A2): same category and plan, one Growth series per fund, live in the last 30 days. IDCW (dividend) options are not included (decided 17 Nov).
  2. Eligibility floor: a fund must have a 3-year return to count in any period. So the 1Y average is over funds that also have 3 years of history.
  3. Weighting: each fund’s return is weighted by its latest average assets under management (AAUM). A fund with no size on record is left out of the weighted figure and counted. If no fund has a size, a plain average is shown and flagged.
  4. Three periods (1Y, 3Y, 5Y), each with the number of funds it covers. A category with fewer than 5 funds is flagged “thin”.
  5. A legacy figure (40% of the 3Y and 60% of the 5Y return, weighted the same way) is still sent for desktop, print and phone views “until the cleanup release”.

The Excel for stakeholders (moved here from Batch E)

A single workbook that explains the category average in as much detail as possible, for every category, and lets a reader check the arithmetic themselves, because the averages are written as live Excel formulas over the listed funds, next to the value the app shows. It is built from the product’s own functions, as the earlier chartered-accountant export is (backend/scripts/export_ca_fund_metrics.py, which calls load_category_pool and category_rank_row and contains no formula of its own), so it cannot drift from the screen.

How the workbook is built, end to end

1. Read the poolThe export script calls the product’s own pool function for every category and plan (read-only, from stored prices).
2. Write the sheetsPool rows as values; Summary figures as Excel formulas over the Pool rows; the app’s value beside each for comparison.
3. Check itselfA test opens the file, recalculates, and compares every Summary formula with the app’s own result (Checks sheet).
4. Stamp itPrice date, size month, fund-list date, export date and the app version on the Read me.
5. Hand it overA download for stakeholders; not committed. The script and its tests are.

How a reader checks one number, by hand

1. Pick a categoryOn Summary, choose “Flexi Cap, Direct” and read its 3Y average.
2. Open PoolFilter the same category. Each fund has its size, 3Y return and a weight (a formula).
3. Multiply and addWeight × return for each counted fund, added up. That is the formula in the Summary cell.
4. CompareIt equals the app’s value shown beside it; Checks says PASS or FAIL.
5. See what is left outExcluded lists every scheme not counted, with the reason (including IDCW).

Rules for the file. Public fund data only: no household, folio, account or member data and no internal ids. The workbook is a deliverable, not committed; the script and its tests are. Every figure carries its date, and the Read me states plainly where a figure cannot be as of a single date (returns end at the latest price; size is monthly). Where the workbook has a number the app does not (the plain average), it is labelled “for comparison only”.

Scope and the chartered-accountant Excel (my defaults). Every category, in both plans. The CA workbook is seven funds with five parameters; this one is every category and one parameter in depth. Both come from one export module, so the category-comparison sheet is built once. If the all-category build proves too large or slow, I narrow it to the categories your stakeholders hold and tell you.
