## What the whole feature does (so you see where your part sits)
The user presses Export PDF; the dialog posts the options; **we start a job that opens our own headless Chromium on the print route with a short-lived pass, waits for the page to say it is ready, prints it to an A4 PDF, and hands the file to the user once**. Three requests (create, status, file) can land on **different worker processes** (the backend runs three), so **job state must be shared across processes**.

## Build
### 1. Settings (`backend/app/config.py`, add; and the production guard in `app/main.py` next to the pass-secret guard)
`export_api_origin: str = ""` (env `EXPORT_API_ORIGIN`, e.g. `https://<the public API host>`: the origin the print page's API calls go to) and `export_job_dir: str = ""` (env `EXPORT_JOB_DIR`; empty means `<export_lock_dir>/jobs`). In production the app **refuses to start** when `export_api_origin` is empty or not `https://`. `FRONTEND_BASE_URL` (existing) is the origin of the print page.
### 2. The shared job store `backend/app/services/export/jobs.py`
Files under the job directory (mode `0o700`; **no database, no migration**; same container file system as the lock files). One job = `<job_id>.json` (status document) and `<job_id>.pdf` (the result, only while it exists). `job_id` is `uuid4().hex` **and every job file name is checked against `^[0-9a-f]{32}$`** (no path from user input ever reaches the file system). Status document: `{ "job_id", "user_hash" (sha256 of the user id, first 16 hex), "status": "preparing"|"ready"|"failed"|"cancelled", "stage": "collecting"|"building"|"finishing", "sections_total": int, "scope_kind": "family"|"member", "created_at", "updated_at", "error_code": null|"busy"|"timeout"|"print_error"|"too_large"|"internal", "pdf_bytes": int|null, "cancel": bool }`. Functions: `create_job(user_id, scope_kind, sections_total) -> job_id` (writes atomically: write a temp file and `os.replace`); `read_job(job_id) -> dict|None`; `update_job(job_id, **fields)` (atomic); `request_cancel(job_id)`; `job_belongs_to(job, user_id)`; `store_pdf(job_id, bytes)`; `open_pdf_once(job_id) -> bytes|None` (**reads and deletes the PDF in one step; a second call returns None**; use `os.replace` to a unique name then read, so two concurrent downloads cannot both succeed); `sweep(now)` (deletes every job file older than **10 minutes**, called at the start of `create_job` and at every status call; a job still `preparing` after **10 minutes** is marked `failed`/`timeout`); `active_job_for_user(user_id) -> job_id|None` (a `preparing` job of that user, found through `user_hash`). The PDF **is a temporary file for at most 10 minutes and is deleted on the first download**: this is the project's "not kept on the server" rule as far as a multi-worker design allows (**flag it in the report so the owner can confirm**).
### 3. The render service `backend/app/services/export/render.py`
`ExportOptions` (Pydantic): `scope: str` (`"family"` or a member UUID string), `section_ids: list[str]` (1 to 40 ids, each `^[a-z0-9][a-z0-9-]{0,59}$`, **de-duplicated in order**; the server does **not** hard-code section names: the print page rejects an unknown id with its error marker and the job then fails as `print_error`), `cover: bool = True`, `data_dates: bool = True`, `show_folios: Literal["full","masked","none"] = "full"`.
`async def run_export(job_id, user_id, options)`: (a) `async with acquire_browser(user_id) as browser` (the pool; map `ExportBusyError` to a failed job with `error_code="busy"`); (b) issue a pass `issue_export_pass(user_id, scope, job_id, now)` **inside** the function (never passed around, never stored, never logged); (c) a **new browser context** per export with `viewport={"width": 680, "height": 1000}`, `color_scheme="light"`, `reduced_motion="reduce"`, `java_script_enabled=True`, `accept_downloads=False`, `locale="en-IN"`; (d) **network allow-list**: `context.route("**/*", handler)` where the handler **aborts any request whose origin is not `FRONTEND_BASE_URL`'s origin or `EXPORT_API_ORIGIN`'s origin** (also allow `data:` and `blob:`), **adds the `X-Export-Proof` header to requests whose origin is the API origin only** (never to the front-end origin, never anywhere else), and counts blocked requests (log the count, never the URL); (e) `page.goto(FRONTEND_BASE_URL + "/print/report#pass=<url-encoded token>&opts=<base64url(json(options.dict + jobId))>")` with a 30 s navigation timeout; **refuse to continue if the page ever navigates to another origin** (listen for `framenavigated`, abort and fail the job); (f) wait up to **90 s** for `html[data-print-ready="true"]` **or** `html[data-print-error="true"]` (poll with `page.wait_for_function`); on the error marker the job fails as `print_error`, on timeout as `timeout`; update `stage` (`collecting` before the wait, `building` while waiting, `finishing` around the print) and honour `cancel` (check the job's `cancel` flag every second during the wait; on cancel close everything and mark `cancelled`); (g) `page.emulate_media(media="print")` then `page.pdf(format="A4", print_background=True, prefer_css_page_size=True)`; a PDF larger than **40 MB** fails as `too_large`; (h) `store_pdf`, `update_job(status="ready", pdf_bytes=N)`; (i) **`finally`: close the page and the context**, release everything, nothing about the pass remains in memory beyond the function. **Logging**: one line at the end: `export finished: status=<s> scope_kind=<k> sections=<n> duration_ms=<d> pdf_bytes=<b> blocked_requests=<c>` (no ids, names, URLs, pass or proof).
### 4. The routes `backend/app/api/export.py` (new router; **one `include_router` line in `main.py`**; the old `POST /analytics/export/pdf` and its payload route stay exactly as they are)
All use the **ordinary session dependency** `get_data_user` (a pass is never accepted here: they are not on the allow-list). `POST /export/report` body `ExportOptions` -> validates scope (a member id must belong to the user: use the existing `require_member`), checks `active_job_for_user` (**409** `{"code": "export_in_progress", "job_id": "<id>"}` so the front end can reopen the running job), creates the job, starts `run_export` as an `asyncio` task (keep a reference so it is not garbage collected; swallow and record any exception as `error_code="internal"`), returns `{ "job_id", "status": "preparing" }`. `GET /export/report/{job_id}` -> the status document minus `user_hash` and `cancel` (**404 for a job that is not yours or does not exist: the same body**). `GET /export/report/{job_id}/file` -> `open_pdf_once`; **404 when not ready, already downloaded, or not yours**; headers `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="Unifolio-portfolio-report-YYYY-MM-DD.pdf"` (**the date is today in IST; no name, PAN, folio or id in the file name**), `Cache-Control: no-store`. `DELETE /export/report/{job_id}` -> `request_cancel`, returns `{ "status": "cancelled" }` (idempotent, 404 for a job not yours).
**Busy mapping:** a job that fails with `busy` carries `error_code: "busy"`; the cooldown and slot limits are the pool's (`user_busy` becomes the 409 above before the job exists; `cooldown` makes `POST` return **429** `{"code": "export_cooldown"}`; `slots_full` fails the job as `busy`).

**Pass-safe guards** (edit the route modules for the routes you list; this is the only place route modules may change; additive; ordinary sessions behave **exactly as today**): under a pass (`is_export_pass(request)` from `pass_token.py`) (a) **`GET /analytics/{scope}` never claims or dispatches a recomputation**: it returns what is stored (the not-ready/updating section states the screen already handles); (b) **snapshots never rebuild, replace or commit**: they return what is stored; (c) any other listed route that can write user-owned rows or start a job gets the same treatment; routes whose only writes are the NAV cache and the shared in-process holdings cache stay as they are (documented in `pass_routes.py` per route). Each guard comes with a test: a pass request to that route makes **no** write and **no** dispatch (assert with the existing test doubles for the dispatcher and the database), while the same request with an ordinary session behaves as before.
