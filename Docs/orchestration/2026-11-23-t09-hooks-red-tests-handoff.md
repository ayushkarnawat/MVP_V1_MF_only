## The interfaces (fixed here; write tests against them, do not write the code)
All four modules are new files in `frontend/src/components/search/`. **`components/search` may import only `getToken` from `features/auth/session` among features; it may import from `shell/` (paths, registry, scope) and `lib/`.** (`noFeatureImports.test.ts` guards this: do not touch it; the build task updates its file list.)

1. **`searchRegistry.ts`**: `export function buildSectionEntries(routes?: ShellRoute[]): SectionEntry[]` (default `buildRegistry()`).
   - For every tab in `SECTION_LISTS` and every section of it: `{ id: section.id, title: section.title, path: <that tab's path from paths.mutualFunds>, tabLabel: <"Overview" | "Performance" | "Allocation" | "Holdings" | "Transactions" | "Overlap" | "Other Analytics">, built: true }` (tab to path: overview `root()`, performance, allocation, holdings, transactions, overlap, analytics `analytics()`). The registry reads F's list; it keeps no list of its own (a test changes nothing: it asserts the entries equal what `SECTION_LISTS` gives).
   - For every shell route with a `path`, `kind !== "group"`, no `redirectTo` and no `:` parameter in the path: `{ id: "page:" + route.id, title: route.label, path: route.path, tabLabel: "", built: route.status === "live" }`.
   - Order: all section entries first (tab order of `SECTION_LISTS`), then pages in registry order.
2. **`usePageSearchState.ts`**: `export type SearchChip = { kind: "category" | "member" | "period"; value: string }`; `export function usePageSearchState(pageKey: string): { text: string; chips: SearchChip[]; setText(text: string): void; addChip(chip: SearchChip): void; removeChip(chip: SearchChip): void; clear(): void }`. State lives in the address: the text in `?q=`, each chip as a repeated `?f=<kind>:<value>` (value URL-encoded by `URLSearchParams`; the first `:` splits kind and value, so a value may contain `:`). Every write uses `setSearchParams(next, { replace: true })` and **keeps all other params** (`sort`, `dir` and anything else). `setText("")` removes `q`; `addChip` adds nothing when the same chip exists; `clear` removes `q` and every `f`; a malformed `f` (no colon, unknown kind, empty value) is ignored when reading. `pageKey` does not appear in the address.
3. **`useSearchIntent.ts`**: `export function useSearchIntent(handlers?: { onOpen?: (open: string) => void }): void`. On mount and whenever the router state changes: read `location.state.searchIntent` **page keys** `section?: string` and `open?: string` (the scope part is the provider's and is already gone). If `section` is set: find `document.getElementById(section)`; if it exists, `scrollIntoView({ behavior, block: "start" })` (`behavior` is `"auto"` under `prefers-reduced-motion`, else `"smooth"`) and set the attribute `data-search-highlight="true"` on it for 1500 ms, then remove it; if it does not exist yet (a lazy section), keep watching the document with a `MutationObserver` until it appears, for at most 5 s. If `open` is a non-empty string: call `handlers.onOpen(open)` once. Then **clear the intent from the history entry** with the router's `navigate(..., { replace: true, state })` (state without `searchIntent`, other keys kept); never `window.history`. Each router entry is handled once (a rerender does not scroll again). The highlight timer and the observer are cleaned up on unmount.
4. **`useScopeJump.ts`**: `export function resolveScopeSwitch(fund: SearchFund, scope: { viewMode: "aggregate" | "member"; memberId: string | null }, members: Array<{ id: string; name: string }>): { scope: "family" | { memberId: string }; label: string } | null` and `export function useScopeJump(): { jumpTo(fund: SearchFund, target?: { path?: string; section?: string; open?: string }): void; switchFor(fund: SearchFund): { scope: "family" | { memberId: string }; label: string } | null }`.
   - Rule (owner decision, Q3): when the page is showing **Family** (aggregate) there is no switch (`null`). When it shows member M: if M is a holder of the fund (any state), `null`; otherwise, if the fund has **one** holder, switch to that person (`label` = their name from `members`, falling back to the holder's `member_name`); if it has **several** holders and M is not one of them, switch to Family (`label` "Family"); a fund with no holders gives `null`.
   - `jumpTo(fund, target)` navigates (react-router `useNavigate`) to `target.path` or, by default, `paths.mutualFunds.fund(fund.scheme_id)`, with state `{ searchIntent: { scope?, section?, open? } }` where `scope` is present only when `resolveScopeSwitch` returned a switch (`"family"` or `{ memberId }`), `section` and `open` only when given. It also records the fund as recently opened through `pushRecentFund(userId, fund.scheme_id)` from `./recentSearches` (the user id comes from `useAuth().me?.user_id`; **but `components/search` may not import `features`: take the id through a parameter of the hook, `useScopeJump(userId: string | null)`, and make the signature `useScopeJump(userId: string | null)`**; call `pushRecentFund` only when `userId` is not null).
   - `switchFor(fund)` is `resolveScopeSwitch` for the current scope (the box shows it as the "switches to X" tag).
   - The hook reads the current scope through `useScope()` from `shell/scope/ScopeContext`.
