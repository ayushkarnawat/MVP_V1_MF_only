Profile design mockups

Layout, section-wise design system, utilities and working UI mockups for the redesigned Profile (desktop, mutual funds only), built from decisions L1 to L41 in the planning workbook. The mockups follow the look of page 31 of the PDF (cards, avatars, pills, outlined buttons, green selection) using the same palette tokens as the Home mockups. All names, numbers and PANs are fictional and illustrative.

Try it: the bar below switches theme, data state (normal, loading, empty, error) and household size (one member or a family) for every mockup at once. Everything is clickable: the left list, family members, member cards, rows, menus, every dialog. Things that would open an existing screen show a short note. "Highlight clickable" outlines every target.
Status: a structural mockup for your review, not pixel-final. Nothing is built. These are companions to the layout doc, the design-system doc and the utilities list in Docs/orchestration/2026-10-23-profile-*.md.

Layout: the page frame

Inside the shell's app layout (sidebar and top bar belong to the shell). Profile draws a title, a left list of seven items with Logout at the foot, and one section at a time (L1, L36). Profile is not scoped: the top-bar selector does not change it.

Left list

About 210 px wide, 40 px rows, 20 px icon, active row in the selected tint. Real router links, so Back and Forward work. Settings stays active on its four child pages. Logout opens the existing confirmation.

Content column

Takes the rest, scrolls with the page, minimum about 640 px. Tables scroll sideways inside their own container. No layout below 768 px: the shell hands over to the mobile tree.

Page map

Personal Information: header card, personal card, Coming soon block. Family: strip and table. Connected Accounts, Tax: Coming soon. Settings: four rows. Subscription: one card. Data & Privacy: four cards.

Scope

None. Member banners are not shown on Profile, as today.

PAN

Always shown masked (first two and last two characters). There is no Show or Hide control and no way to see the full PAN on this screen (L49). No PAN: "Not added". A PAN held by another account: masked, with a "Held by another account" tag.

Design system: colour tokens

Source: Docs/Unifolio Colour Palette.pdf, as adopted for Home and the shell (scoped tokens, tokens.css untouched). Profile adds no new colour. Values below are read live from the current theme.

Where Profile uses colour

Selected tint behind the active list item and the "Admin" pill; primary green for the Add Member button and focus rings; informational tint for the "Member" pill; warning tint only if a pending PAN note is shown; neutral tint for "Coming soon" tags; negative text and border only for Delete account and errors.

Green is rare

One or two green elements per screen: the active list item, one primary button, the focus ring.

Fonts

DM Sans for headings, Manrope for body, tabular numerals for PAN and dates.

Personal Information

Opens here (L13). The header card carries name and PAN (so the Personal Information card no longer repeats them, L46). Financial Details now shows what onboarding already stored: investor type and goals, with an Edit that reuses the onboarding call (L43). Everything else there is Coming soon. No date of birth, address or photo (L18, L19).

Mockup (interactive)

Source

Account call (name, email, phone, created date, investor type, goals); household list (PAN, members).

Onboarding answers (try the "Onboarding data" buttons above)

Goals are stored as a JSON array of option codes, so the card maps each code to the title shown in onboarding, in the onboarding order. A null or empty list shows "Not answered" with an Add button. A code this screen does not know yet is shown humanised in a dashed chip, never dropped. "All of it" in onboarding saves the four real codes; when all four are stored the card shows one "All of it" chip (L52).

Actions

Edit Profile: existing Complete profile dialog. Change email or mobile: new contact-change dialog. Edit goals or investor type: saved with the existing PATCH /auth/me, so no backend change.

Family Members

Strip in the PDF's style (L23). Its last tile is now "Add statement": it asks who the statement is for, then opens the upload options (L45). The member list keeps today's card layout, including the profile-completion chip, instead of the PDF's table (L47). The Admin or Member label stays (L6).

Mockup (interactive)

Source

Household members list (name, PAN, relationship, phone, email, profile completion, missing fields).

Completion chip

Below 100% the card shows "60% complete · Finish profile" (or "Add email" when one field is missing) with a progress ring; at 100% it becomes an Edit profile button. Same behaviour as today.

States

Empty shows "No family members yet" and the tile goes straight to upload. The fourth member's PAN is held by another account, so it has no Show control.

Rules

Merge happens only inside Edit's possible-duplicate prompt. There is no Add Member button now: people come in through statements. "Delete member" (every member except the Admin) sits above "Delete all funds" and removes the person and their funds.
