## Contracts (to be turned into exact per-step specs and tests)
- **`ScenarioCard({ scenario, selected, onSelect })`** (mockup `.m-sc`): a `<button type="button">` whose accessible name is its text; type icon tile 40 px (`CRASH` `TrendingDown` on a `--neg-bg` tint with `--neg`; `BULL_RUN` `TrendingUp` on a 14 percent `--c2` tint; `POLICY_RATE` `Percent` and `HYPOTHETICAL` `Sparkles` on a 14 percent `--c4` tint); name (`line-clamp-2`, semibold 13.5 px); dates `formatDateRange(start, end, is_ongoing)` from `@/lib/dateRange`; description line (`line-clamp-2`, full text in `title`; **element omitted when `description` is `""`**); stat `Nifty 50: ${signedPct(quick_market_pct)}` in the gain or loss text token, none for a hypothetical, a freeze (`had_redemption_freeze_schemes` non-empty) or a multi-phase scenario or when `quick_market_pct` is null; badges at the top right: `Freeze` (`Snowflake`, `--warn` border, `--warn-text`, `--warn-bg`), `ongoing` (dot in `--neg`), `Assumption-based` (see open point); `ChevronRight`; selected: `border-2 border-[var(--pos)] bg-[var(--pos-bg)]` (the only green on the list).
- **`ScenarioList({ curated, all, selectedId, onSelect, isLoading })`**: loading 8 skeleton cards (`role="status"`, text `Loading scenarios`); both lists empty `NO_SCENARIOS`; curated cards first (grid 2 columns, 3 from 1024 px, 5 from 1280 px); `More scenarios` / `Hide` button (`aria-expanded`, `aria-controls="more-scenarios"`; shown only when scenarios remain beyond the curated ones); when open, pills in `<div role="group" aria-label="Scenario categories">` (`All`, `Crashes`, `Bull Runs`, `Policy / Rate`, and `Hypothetical` only when `all` has such a scenario; each `aria-pressed`) filtering **only** the remaining cards; the selected card stays selected when a pill hides it (never `onSelect(null)`, L38). Grouping logic copied from the classic picker (`curatedIds`, `remaining`), not imported.
- **`ScenarioDetail({ result, members, selectedMemberId, onMemberChange, refreshing, onImport, onLearnMore })`**: heading row (`h2` with the name, `tabIndex={-1}` so the flow can focus it; dates; description; `MemberSelect` at the right, not shown in the no-holdings state), then the disclaimer `COMPLIANCE_COPY` (+ `ONGOING_SUFFIX` when ongoing) in italic secondary text, then by shape (`resolveShape` and `buildTiles` from PL-A): **standard**: tiles row, chart row (`BenchmarkChart`, `AssetClassChart`, `MiraInsightsCard`; `min-[1280px]:grid-cols-[5fr_6fr_4fr]`, from 1024 px two charts with Mira full width below, below 1024 stacked), `MemberRows`; **multi-phase**: tiles (no benchmark tile), three phase cards (`ol`, sorted by `order`: label, `formatDateRange`, percent in tone colour, `NO_DATA` when null, an ongoing dot), `AssetClassChart` and Mira, `MemberRows`; **redemption freeze**: banner (`Snowflake`, `FREEZE_HEADLINE`, `FREEZE_BIG` in the warn colours) when any member fund `is_frozen`, otherwise `NONE_FROZEN`, then `MemberRows`, no tiles or charts; **pre-2006** (`funds_data_available === false`): the benchmark tile, the note card (`Info`, `PRE_2006_NOTE`), `BenchmarkChart` without a portfolio bar and Mira, no member rows; **no holdings** (`total_value` null or zero and every member's funds empty): note card with bold `NO_HOLDINGS_TITLE`, `NO_HOLDINGS_LINE` and a button `IMPORT_LABEL` that calls `onImport`; no tiles or charts; **hypothetical**: renders nothing (the list never offers it while the backend flag is off). While `refreshing` the tiles and charts sit in a wrapper with `opacity-60` and keep their content. A 200-character name wraps (`break-words`), a one-member household still renders the dropdown.
- **`PlanningScenarios(props: PlanningBinding)`** with `interface PlanningBinding { selectedId: string | null; onSelect: (id: string | null) => void; onImport: () => void; onLearnMore: () => void }`: loads both lists on mount (abort on unmount; error card `LIST_ERROR` plus the message and `TRY_AGAIN`, `role="alert"`); with a `selectedId` loads the family result (`getScenarioResult(id, signal)`), derives `members` once from the family result's `by_member` entries whose `funds` is non-empty and keeps them while the member changes, refetches with `memberId` when the dropdown changes (the previous result stays on screen with `refreshing`), keeps the chosen member across scenarios (a ref), reverts the dropdown and shows the error in the detail when a member fetch fails, shows skeleton tiles and two skeleton chart cards for the first load (heading from the list data), and scrolls the detail heading into view with `behavior: "smooth"` unless `window.matchMedia("(prefers-reduced-motion: reduce)").matches`; focus moves to the heading.
- **`PlanningPage()`** (default export): state `{ view: "landing" | "future" | "market"; scenarioId: string | null }` with `planningHistory` (PL-A): on mount `replacePlanningState({ planning: "landing", scenarioId: null })` (a refresh returns to the landing); choosing a card or a scenario calls `pushPlanningState`; a `popstate` listener restores the state from `readPlanningState()` (null means landing); Back to Planning (`ChevronLeft`, `BACK_LABEL`). Future: heading `PLAN_FUTURE_TITLE`, line `PLAN_FUTURE_LINE`, a note card (`Sprout`, bold `COMING_SOON_TITLE`, `COMING_SOON_LINE`), no controls. Market: heading `EXPLORE_TITLE`, subtitle `MARKET_SUBTITLE`, `PlanningScenarios` with `onImport` = `useImport().openImport()` and `onLearnMore` opening the shell `MiraComingSoonDialog` (`@/shell/mira/MiraComingSoonDialog`, props `open` and `onOpenChange`).
