## 6. The process, in full (how every task is run)
**The cycle for every worker task** (same since the UI redesign, refined in the 2026 waves):
1. **Wave-start check:** re-read the code the plan names, report drift in the handoff (do not silently adapt). Read-only audits go to read-only subagents that write one document.
2. **Write the handoff (Codex) or packet (Antigravity)** in `Docs/orchestration/`, named `YYYY-MM-DD-<task>-handoff.md` or `-packet.md`. Look at the existing ones as templates: **`2026-11-20-d4-several-benchmarks-handoff.md`** (backend), **`2026-11-20-d10-day-change-dialog-packet.md`** and **`2026-11-20-d6c-benchmark-data-path-and-legend-packet.md`** (frontend), **`2026-11-20-f5-rail-red-tests-handoff.md`** (tests only). Fixed sections: status and approval; parent plan and spec (the workbook is the design); worker and constraints (Codex cannot run X); work-in path (worktree or clone) and branch; read-first list (`ui-common-rules-*`, `wave-common-rules.md`); the interfaces (names and signatures, decided by you); the change (additive, old payloads unchanged); tests first (names, red for the stated reason); run-these-only commands; files you may touch and may not touch; constraints (invented data, no network, no new dependency, git read-only, no deletion flags); report format (one fenced block: counts before and after, commands and results, `git status --short`, decisions the packet did not cover, what could not be checked, open questions); a **paste-ready prompt** at the end.
3. **Relay:** the owner pastes the prompt into Codex or Antigravity. You always give her the prompt **inline in the chat in a code block** (she copies from there), one block per worker, with the worktree or clone path named. Codex prompts say "reply with the CODEX REPORT block, nothing else".
4. **Report intake (what you do when she pastes a report):** (a) read it critically (a worker's "BLOCKED on running" is expected for Codex); (b) **run the tests yourself** in the right place: back end with `D:\Unifolio code\backend\.venv-win\Scripts\python.exe -m pytest <files> -q -p no:cacheprovider` from the worktree's `backend/`; front end through `Docs/orchestration/wave-fe-check.sh <lane> test|types|lint|build [paths]` (see section 12); (c) read the diff, check the allowed-files list, confirm the new tests were red for the stated reason (for a frontend worker's claim, re-run on the old code if in doubt); (d) fix fallout yourself (small) or send exact corrections; (e) **commit in the clone or worktree** with explicit `git add` paths and a message that ends with the attribution line the harness gives you; (f) fetch the clone branch into the batch branch (`git fetch <clone-path> <branch>:refs/heads/<branch>` then `git merge`), resolve, run the wider suites; (g) update `Docs/orchestration/delegation-log.md` and `decisions.md` (one line per decision), the batch tracker if there is one; (h) tell the owner plainly what is verified, what is not, and what is next, with the next prompts ready.
5. **Reviews and gates:** a fresh read-only reviewer reads the diff against the plan's "Review Focus" and the owner's decisions, returns ranked findings with file, line and a scenario; **a finding is closed only when fixed (red test first) or explicitly accepted by the owner** (ask with a recommendation; "whatever you recommend" from the owner means accept your recommendation). ## 12. Environment, tools and pitfalls
**Layout on the first laptop (Windows 11, WSL Ubuntu):** main checkout `D:\Unifolio code`; worktrees `D:\unifolio-*`; Antigravity clones `C:\Users\Ayush\ag-*`; scratchpad per session. `wave-fe-check.sh` has these paths **hard-coded** (`/mnt/d/unifolio-*`, `/mnt/c/Users/Ayush/ag-*`): on a new laptop keep the same drive and user, or edit the `case` lines for the lanes. Lanes: `b c a af ax aw d h l m1 m2 dp do di ks ed fn` (worktrees) and `ag-<name>` (clones). It mirrors the lane into WSL `~/cr6-fe-<lane>` with `node_modules` hard-linked from a base `~/cr6-fe/node_modules` (build the base once: copy `frontend/` to `~/cr6-fe` and `npm ci` with Node 20.20.2 via nvm at `~/.nvm/versions/node/v20.20.2`); modes `test|types|lint|build`; a folder test takes about a minute, the full suite about 6 minutes.
**Back end:** Windows venv `backend/.venv-win` (create with `python -m venv backend\.venv-win` and `pip install -r backend/requirements-dev.txt`); run pytest from the worktree's `backend/` with that venv's `python.exe`; the full wide run takes about 12 minutes; Postgres-only tests skip without `TEST_DATABASE_URL`. Some real-data disclosure tests skip when `backend/.cache/amfi_navall/nav_all.txt` (git-ignored) is absent.
**Staging access:** SSH only from WSL as `deploy@ls-redesign.unifolio.in` (the Windows key is refused). **On a new laptop the key and the IP are new:** the owner must add the laptop's WSL public key to the VM's `authorized_keys` and, if SSH times out while HTTPS works, add the laptop's public IP to the CloudPe security group (an SSH timeout with HTTPS working is the CloudPe allowlist, not a VM fault; see the runbook). Never click Detach on the VM's Networking tab. `gh` must be logged in (`gh auth login`) for pushes (account `ayushkarnawat`; the repo remote is HTTPS).
**Other tools:** LibreOffice at `C:\Program Files\LibreOffice\program\soffice.exe` (recalculate workbooks so values show on a phone); `pypdf` for PDF text extraction in WSL (the web-fetch agent returns raw PDF bytes); the in-app Browser tools for harness pages (a dev server inside WSL is **not** reachable from Windows: build a static bundle into the scratchpad and serve it with a tiny Python server with HTTP Range support; stop servers by port with PowerShell).
**Pitfalls (each cost time once):**
- **Never pass shell variables through `wsl.exe` inline** (`$VAR`, `~` expand in the outer shell; a read-only agent once ran `rsync --delete` to `/` this way). Put WSL commands in a script file, or write every value out. Subagent briefs forbid `rsync --delete`/`rm -rf` outside scratch.
- Bash heredocs with `'`, `\u`, `\b` or Windows paths inside Python source break (unicode-escape errors, parse errors that abort the whole command silently): write Python or TSX edits with the **Write tool** into a script file in the scratchpad and run it; use forward slashes in paths.
- `tar` treats `C:` as a remote host (`--force-local`); scp from Git Bash fails (SSH only from WSL).
- Windows default encoding is cp1252: always `encoding="utf-8"` when a test or script reads repo files.
- Fixed dates in tests age out (a news test hard-coded 27 Oct and failed from 10 Nov on every machine): date test data from the real clock.
- A docs commit on `leapswitch-redesign` is invisible to a worker branch until merged: merge docs into batch branches and refresh clones before relaying.
- Background tasks: use Monitor with an until-loop (not `sleep` chains); never poll output files of subagents (they are transcripts).
- Read before Edit: the Edit tool refuses a file you have not read in this session.
- Vite builds split into lazy chunks: grep every chunk when checking that new strings are live.
