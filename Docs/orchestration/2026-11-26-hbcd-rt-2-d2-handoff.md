## What and why
Today the Request button is a `<Button>` that opens the floating checklist and then calls `window.open` for CAMS; browsers block that second open after the floating window appears, so the checklist has an extra "Open the CAMS form" button. After D-2: the Request button is a real `<a>` whose own link behaviour opens CAMS in a new tab, and whose click handler **first** calls the checklist open (the floating window must be requested synchronously from the click) and **never calls `preventDefault`**; the request to the server is sent right after, in the background. The checklist no longer needs an "open the CAMS form" button or a "getting your link ready" state.

## The contract (fixed here; the Antigravity lane builds to it)
- `getCamsLink(): Promise<string>` already exists in `features/import/api.ts` (hbcd-rt-1). `RequestCamsPath` **prefetches it on mount** so the link's `href` exists at click time; the Request link is **disabled** (rendered as the same-looking control with `aria-disabled="true"`, no `href`) only while the address loads or if it failed to load (then it falls back to today's behaviour: a button that requests, then `window.open`s the address returned by the request).
- The Request control (desktop, link available) is `<a href={camsUrl} target="_blank" rel="noopener noreferrer" data-clickable="" data-effect="open">` with the accessible name **`Request Statement on CAMS`** (the same words as today), styled as today's green button.
- Its click handler: (1) calls `checklist.open()` **synchronously, first** (before any `await`); (2) does **not** call `preventDefault`; (3) then sends `requestCamsStatement(memberId)` in the background; (4) on success calls `onRequestInitiated(importId, expiresAt)`; (5) **does not call `window.open`** for the CAMS address (the link already opens it) **unless** the link was not available (fallback above); (6) a failed request shows the existing error in the checklist with its "Try again" and nothing else breaks.
- Checklist: `checklistCopy.open` ("Open the CAMS form") and `checklistCopy.preparing` ("Getting your link ready") are **removed**; `CamsChecklist.tsx` has **no** "Open the CAMS form" button; the store has no "link ready/preparing" state.
- Phone (`frontend/src/mobile/**`): unchanged; it keeps calling `requestCamsStatement` and opening CAMS as today.
