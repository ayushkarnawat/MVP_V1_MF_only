# PRD: Navigation shell (left sidebar and top bar), desktop (draft v1)

**Status:** draft, 2026-10-23. Doc 7. New document; existing PRDs (PRD-01 to 04) are **not edited**. Conflicts with earlier statements are in section 9 for the owner. Source of truth: `Docs/Web app UI mockups MFs.pdf` pp. 2-3, 9, 10; `Docs/Unifolio Colour Palette.pdf`; decisions L29 to L39 and N1 to N13 (artifact `2026-10-22-left-panel-plan.html`).

## 1. Problem and goal

The desktop app navigates with a top bar of five tabs, held in React state, with no URLs. The redesign needs a left sidebar every page lives inside, real URLs (deep links, refresh, back), and a way for two people to add pages in parallel without editing shared files.

## 2. Users

Households with one or several members, and the two people building pages.

## 3. Scope

**In:** router and route registry; sidebar (main mode and Portfolio mode with an expandable Equity group); top bar frame; family-or-member scope with its reset rule; Back; focus layout for import; standard states; wrapper routes for the existing screens; placeholders for every unbuilt page.
**Out:** mobile; changes to existing screens; page contents (Home, Investments, Mutual Funds sub-pages and the rest); the search box's behaviour (on hold, L46); backend changes; moving `tokens.css` to the new palette.

## 5. Non-functional

Route pages load lazily; only registry metadata is eager. First paint of the shell does not wait for pages. No live network in tests; run only affected tests. No new backend dependency. One new frontend dependency (`react-router ^7.18.4`).

## 6. Success measures (proposed; the app has no event tracking today)

A page owner can add a page by editing one file; zero regressions in existing screens after PR 2 (the ported tests pass); no console errors on deep links. Usage metrics need an owner decision (SB4).

## 7. Risks

Moving state out of `MainDashboardFlow` can change member defaults, banners or the import notice (mitigation: move logic unchanged, port the tests first). Landing on the Home placeholder (SF1) is accepted: staging waits for all pages. The two temporary pieces (tab strip, Add data button) can linger if nobody removes them; each has a test so removal is deliberate (SF2, SF3). A palette change to the shared tokens would alter existing screens (SP2). The manager plans against the contract; changes need a notice (D4).

## 8. Rollout

PR 1 (`feat/shell-nav`): router, registry, sidebar, top bar frame, placeholders, tests; not switched on. PR 2: scope move, wrappers, `App.tsx` switch, retire the old shell, port the three test files. Then page branches. Both owners review everything under `frontend/src/shell/` (CODEOWNERS). Staging check on a two-member synthetic household.
