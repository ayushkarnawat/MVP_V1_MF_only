## How a print section works
- The route renders `PRINT_SECTIONS[id].render()` inside `<section data-print-section="<id>">`, inside `PrintModeProvider` and a minimal scope provider (family or one member), at a fixed width of **680 px** with the light theme forced and animations off. Outside print mode the screens behave exactly as before: **every existing test must pass untouched**.
- **Your group has its own file**: `frontend/src/print/groups/<group>Print.tsx` exports `<group>PrintSections: Record<string, () => ReactNode>` (empty today). Add one entry per section id of your group; any id you do not add keeps the placeholder. **Edit only your group file for registration.**
- **Each entry is a small wrapper component** that does what the page does for that section: calls the same data hooks (`useMfDashboard()`, `useMfAnalytics(...)`, `useMfHoldings()`, `useMfHistory()` and so on, see the page file), passes the same props, renders the section **in its ready state**, and **calls `usePrintSettled(id, settled)`** from `frontend/src/print/usePrintSettled.ts` with `settled = true` once the data is loaded **or** the section's own failed state is showing (a failed section prints its failure sentence and the report still becomes ready). Never render the page component (it needs the frame: `useMfFrame()` throws outside `MutualFundsFrame`, and the page adds the tab bar, search and section rail). Put wrapper components that are new in **`frontend/src/print/groups/<group>/`** (new folder, your own), **not** in `frontend/src/features/mutual-funds/` (its guard test counts the files there).
- **LIGHT variants** edit the existing section component to read `usePrintMode()` and, only when it is non-null, hide controls, open collapsed content, drop `min-width` and scroll wrappers, and replace tooltips with visible text. **HEAVY variants** are new print-only components in your `print/groups/<group>/` folder that use the same data and the same helpers (formatting, labels, dates) as the screen: **same numbers, same wording, dates through `formatDataDate`/`DataDateLabel`** (never typed words; a repo test forbids a literal "as on"/"as of" outside the allowlist).
- **Print-mode rules** for everything you touch: no `<button>` in the printed output (a test in your group checks the rendered DOM of each entry), no `title`/hover-only content that a reader needs, no sticky or fixed elements, no scroll containers with a max height, tables use fixed layout with repeated headers (`thead`) and `tr` that do not split (`break-inside: avoid`), lists use `li { break-inside: avoid }`, page search text and chips are **never** applied (the print wrapper passes an empty query), nothing fetches on interaction. The sections' `InfoMark`s and Retry buttons are already gone via `SectionCard`/`InfoMark`; do not add new ones.
- **Folios** follow `usePrintMode().folios` through `FolioNumber` (already done); never print PAN in any form.
- **Charts**: do not change shared chart components (`features/mutual-funds/common/charts.tsx`, `components/ui/charts/**`, `components/wealth-graph/**`): they are shared by several groups. If you need a change there, **stop and put it in the report** (the orchestrator makes shared edits). You may pass props the component already has (`width`, `selectedKey={null}`, `activeKey={null}`, a fixed height).
- **Page breaks**: a section is allowed to split between rows; use `break-inside: avoid` on rows and on small cards, never on a whole large card. Heading and first row stay together (`break-after: avoid` on headings).
