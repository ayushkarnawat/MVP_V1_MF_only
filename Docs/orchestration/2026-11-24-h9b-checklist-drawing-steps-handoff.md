## The logic change (the only real one)
Today `markFileReady()` closes the checklist and clears its state at once. **New:** `markFileReady()` moves the step to **`ready`** (saved with the ticks, shown in the window as W3) and **keeps the window open**. A new action **`finish()`** (the W3 button `Close this checklist`) closes the window, clears the saved state, sets a flag **`finishedFromChecklist`** in the store (in memory) and makes the container show the upload screen. Closing the floating window by its own x while on `ready` does the same as `finish()` (clear state, show upload, set the flag).
- **The early-return jump (decision 5 of H-9 changes slightly):** while the checklist is open and the step is `form` or `waiting`, do not jump to the upload screen on window focus (as built). **When the step is `ready`, the jump is allowed**: returning to the tab shows the upload screen, and the window stays up showing W3 until the user closes it. The upload screen shows the **UP banner** while `finishedFromChecklist` is true and until the user presses Import or leaves the screen (then the flag clears).
- **Reload on `ready`:** the saved step is `ready` and the window is gone, so the screen offers the closed card (RO) naming `step 4: You have the file`; "Reopen checklist" reopens on W3.
- **Step names in the closed card and the panel title** (the drawing names only one: `step 2: Fill the form`; I am extending it in the same pattern, flag for the owner): `form` is `Step 2: Fill the CAMS form`, `waiting` is `Step 3: Wait for the email`, `ready` is `Step 4: You have the file` (the numbers count the request screen as step 1).
