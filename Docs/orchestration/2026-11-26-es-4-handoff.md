## What and why
At start-up the app launches a headless browser for the **old** analytics "Download PDF" route in **each of the three workers**, and keeps it running all day; staging measurements found about 90 MB idle per browser. The new export does not use it. **Launch it on first use instead**, so start-up launches none; the old route keeps working.

## The contract (fixed here)
`get_shared_browser()` **launches the browser on first use**: an `asyncio.Lock`-guarded lazy start, so two concurrent first requests launch **one** browser; later calls return the same one. `main.py` **no longer calls `start_browser()`** in the lifespan. `stop_browser()` and `close_pool()` **still run at shutdown** and are **no-ops when the browser was never started**. If the shared browser has crashed or disconnected, the next `get_shared_browser()` launches a fresh one (keep whatever recovery the code has today). **The old route (`/analytics/export/pdf`), its payload and its response are unchanged.** `start_browser()` may remain as a public function (other code or tests may call it), but nothing calls it at start-up.
