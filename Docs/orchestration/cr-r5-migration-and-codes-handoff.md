### API contract for Run 6 (as built)
All under `/auth/head-change/`, bearer session, active-user check (pending deletion: 403 `{detail: {code: "account_pending_deletion", message}}`). Errors: HTTP status plus `detail: {code, message}`.
- `POST start-code` body `{to_member_id}` (after T5.4b; before it, `{}`) -> `{message: "Code sent.", otp: "123456" | null}` (`otp` only in stub mode). Errors include `current_email_missing`, `otp_throttled` (429), `email_send_failed` (502).
- `POST start` `{to_member_id, current_head_code}` -> `{request: <status>, codes: [{party, channel, verified, otp}] x4}` with the current email already verified (`otp` null). Errors: `wrong_code` 401, `code_locked` 401, `code_expired` 410, `member_not_found` 404, `head_change_already_open` 409, `member_not_eligible` 409, `contact_same_as_head` 409, `contact_in_use` 409, `pan_registered_elsewhere` 409, `import_in_progress` 409.
- `POST verify` `{request_id, party: current|new, channel: email|phone, code}` -> `<status>`. `request_not_found` 404, `request_expired` 410, `wrong_code`, `code_locked`.
- `POST resend` `{request_id, party, channel}` -> `{request: <status>, code: {party, channel, verified, otp}}`; `otp_throttled` 429 carries the app's wait message.
- `POST cancel` `{}` -> `<status>` with `status: "cancelled"`; `GET pending` -> `{request: <status> | null}`.
- `<status>` = `{request_id, status: "pending"|"ready"|"cancelled"|"expired", expires_in_seconds, verified_count, ready, current_email_verified, current_phone_verified, new_email_verified, new_phone_verified}`; `ready` is derived (the row stays `pending` until Task 5.5 completes it).
