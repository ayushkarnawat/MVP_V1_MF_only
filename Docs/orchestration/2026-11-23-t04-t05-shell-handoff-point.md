## T05: scope intent (test first, on the REAL provider)
**Purpose:** a search jump to a fund held only by another member must land on that member (or Family) and survive the reset rule; Undo restores the previous selector (K plan Global Constraints; spec traps; owner decision Q3 and Q19 A).
**Interfaces**
- New `frontend/src/shell/scope/scopeIntent.ts`: `export type ScopeIntent = { scope: "family" } | { scope: { memberId: string } }`; `export function readScopeIntent(state: unknown): { scope: "family" | { memberId: string } } | null` reads the one-time router state key **`searchIntent`** (`{ scope, section?, open? }`; **only `scope` is the provider's business**; `section` and `open` are for the page, T09/T11+); returns `null` for anything malformed.
- `ScopeProvider` applies the intent **once, after the reset rule has run** (so the reset cannot undo it): when `locationState` carries `searchIntent` with a scope and `state.ready` is true (if the household is not loaded yet, defer until it is), set the pick (`family` -> aggregate via the existing default pick; a member id -> member mode if that id is in `members`, otherwise ignore), **remember the previous pick**, then **clear the intent** from the history entry (use `useNavigate` with `replace: true` and the same path and search, dropping `searchIntent` from the state but keeping other keys such as `importNotice`; mark the location `key` as handled in a ref so it is applied once even in StrictMode). **Do not use `window.history` in `src/shell`.**
- **Undo (design decision of the orchestrator, adjustable):** extend `ScopeValue` with an optional `scopeJump?: { label: string; undo: () => void } | null`; it is set when an intent changed the selector (the `label` is the member's name or "Family"), `undo()` restores the remembered pick and clears it, and it is also cleared by any manual selector change and by navigating to another page. The notice component in T08 (`SearchNotice`, Antigravity) reads it through `useScope()`. Keep `ScopeValue`'s existing members unchanged (the many existing test providers must still type-check: make the new field optional).
**Tests first (names from the K plan; on `ScopeProvider` itself, not `TestScopeProvider`, whose `setAggregate` behaves differently):** `a jump from Home with intent member Asha ends on Asha after the reset rule`; `a jump with intent family ends on family`; `intent is applied once and cleared`; `no intent: the reset rule behaves as today` (the existing `ScopeProvider.test.tsx` cases stay green); `Undo restores the previous selector`; plus `an intent for an unknown member id is ignored`; `intent that arrives before the household loads is applied after it loads`; `a manual selector change clears the undo`. Build the router wrapper the way `ScopeProvider.test.tsx` does (look at it first), navigating with `{ state: { searchIntent: ... } }`.
