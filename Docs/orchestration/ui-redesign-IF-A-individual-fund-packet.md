**`useFundSection.ts`** (12 tests). Types and behaviour:
```ts
export type FundSectionStatus = "loading" | "ready" | "unavailable" | "error";
export interface FundSection<T> { status: FundSectionStatus; data: T | null; reason: string | null; error: unknown; retry: () => void }
export function useFundSection<T>(fetcher: (signal: AbortSignal) => Promise<T | Unavailable>, deps: readonly unknown[], options: { enabled?: boolean } = {}): FundSection<T>
export function useFundPageScope(): string
```
It is `features/home/useHomeSection.ts` (read it) with these changes: (a) the state also carries `reason`; (b) a resolved body whose `status` is `"unavailable"` gives status `unavailable`, `data` null and `reason` the body's reason, any other body gives `ready` with the body as `data`; (c) the key that restarts the request is `` `${JSON.stringify(deps)}#${attempt}#${enabled}` ``; (d) `options.enabled` (default true): when false no request is made and the status stays `loading`; (e) on a key change it shows `loading` with `data`, `reason` and `error` null **at once** (during the same render, not after an effect), a late answer or failure of an aborted request is ignored (check `controller.signal.aborted` and ignore `AbortError`), unmount aborts, `retry()` goes back to `loading` and fetches again, an unchanged dependency list on re-render does not refetch, and a new fetcher function alone does not refetch (keep the latest in a ref). **`useFundPageScope()`**: `const { viewMode, memberId } = useScope();` returns `memberId` when `viewMode === "member"` and `memberId` is set, otherwise the word `"combined"`.
