# Handoff: i5c-two-pass-pages (Batch I: contents page numbers by printing twice, backend, Codex A)
**Status:** READY TO RELAY **after the owner confirms the one new back-end dependency, `pypdf`** (written 2026-11-24). Milestone M4. A browser cannot know on which page a section will land until it has printed, and the contents page must show page numbers (sample pages 2 and 3). So the render service **prints the report twice in the same open page**: the first print finds where each section landed, then the contents are filled in and the report is printed again. Front-end side (built in `2026-11-24-i9b-template-integration-handoff.md`): every section wrapper starts with an invisible marker text `[[sec:<section id>]]` and the notes page with `[[sec:notes]]`, and the page exposes `window.__unifolioSetPrintPages(map)` (a promise that resolves after the next animation frame) that fills the contents' page numbers **without reloading or refetching**.

## The change
1. **Dependency (owner-approved):** add `pypdf` to `backend/requirements.txt`, pinned to an exact version at least two weeks old that you know (for example `pypdf==5.1.0`), pure Python, BSD licence, no system libraries. Nothing else is added.
2. **`backend/app/services/export/pdf_pages.py`** (new): `extract_page_texts(pdf: bytes) -> list[str]` (one string per page, using `pypdf.PdfReader`; a page whose text cannot be read gives `""`; a PDF that cannot be opened raises `PdfPagesError`) and `section_pages(texts: list[str]) -> dict[str, int]` (the **1-based page of the first occurrence** of every marker matching `\[\[sec:([a-z0-9][a-z0-9-]{0,59})\]\]` in the page texts; keys are the section ids and `notes`). Pure functions; no file system, no logging of text.
3. **`render.py` (`run_export`)**: after the page reports ready and before the PDF is stored: **print once** (as today, `stage` = `building` then `finishing`); **if the options asked for the cover** (`options.cover`, because the contents exist only with the cover) compute `section_pages(extract_page_texts(first_pdf))`; **if every requested section id and `notes` were found**, call `await page.evaluate("window.__unifolioSetPrintPages")` with the map (as JSON argument; **verify the function exists first** with `typeof window.__unifolioSetPrintPages === 'function'`, and if it does not, keep the first PDF), wait for it to resolve (timeout 10 s), print **a second time** with the same settings, and use the second PDF **only if its page count equals the first's** (the contents page count must not change); otherwise keep the first PDF. Any failure of the second pass (exception, timeout, a missing marker, a different page count) **keeps the first PDF and does not fail the job**. The size limit applies to the PDF that is kept. The `stage` stays `finishing` during the second print. **Log line** (the existing final line) gains only `two_pass=<yes|no>`; nothing about the text, the markers or the page numbers is logged.
4. **The fragment** gets no new key: the first print has no `pages`; the page numbers go in through the hook. (`options.pages` exists on the front end for tests and for the fallback page; the back end does not send it.)
