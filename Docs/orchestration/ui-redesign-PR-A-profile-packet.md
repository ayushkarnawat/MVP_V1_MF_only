- `export const GOAL_OPTIONS: ReadonlyArray<GoalOption>`, in this order, strings exactly: `consolidated_view` / `Consolidated portfolio view` / `See all my mutual funds across every broker and fund house in one place`; `understand_holdings` / `Understand true performance` / `See your true returns after fees, taxes and plan type`; `family_management` / `Family wealth tracking` / `Managing investments for family members under one dashboard`; `performance_comparison` / `Compare distributor fees` / `Compare returns and costs across different distributors`.

- `export function humanizeCode(code: string): string`: every run of underscores becomes one space, trim, upper-case the first character, the rest unchanged; `""` stays `""` (`retirement_planning` gives `Retirement planning`, `x__y` gives `X y`, `_lead_and_trail_` gives `Lead and trail`).

**`goalChips.ts`**
- `export interface GoalChip { label: string; unknown: boolean }`.
- `goalChips(codes: readonly string[] | null | undefined): GoalChip[]`: ignore empty strings and repeats (first appearance wins). Known codes are the four `GOAL_OPTIONS` values. If **all four** are present: one chip `{ label: "All of it", unknown: false }`. Otherwise one chip per known code present, **in `GOAL_OPTIONS` order (not stored order)**, `{ label: title, unknown: false }`. Then one chip per unknown code, in stored order, `{ label: humanizeCode(code), unknown: true }`. `null`, `undefined` and `[]` give `[]`. Never changes its input.
- `mergeGoals(current: readonly string[] | null | undefined, selectedKnown: readonly PrimaryGoal[]): string[]`: the selected known codes in `GOAL_OPTIONS` order without repeats, followed by the stored codes (from `current`) that are not one of the four known codes, in stored order, without repeats and without empty strings. (`mergeGoals(["x_y","consolidated_view"], ["family_management"])` gives `["family_management","x_y"]`: a stored code this build does not know survives a save; a stored known code the user unselected is dropped.)

**`investorLabel.ts`:** `investorLabel(code: string | null | undefined): string | null`: `null` for null, undefined or `""`; the `INVESTOR_OPTIONS` title for a known code; otherwise `humanizeCode(code)`.
**`accessLevel.ts`:** `accessLevel(relationship: string | null | undefined): "Admin" | "Member"`: `Admin` only when the value is exactly `self` (case-sensitive, no trimming); everything else, including null, `Member`.
**`accountType.ts`:** `accountType(memberCount: number): "Individual" | "Family"`: `Family` for two or more, otherwise `Individual` (0 and 1).
**`initialsOf.ts`:** `initialsOf(name: string | null | undefined): string`: first remove a trailing `(Me)` (case-insensitive, with the spaces before it: the household list names the self member `Alice Rao (Me)`), trim, split on whitespace; no words gives `?`; one word gives its first character upper-cased; two or more give the first character of the first and of the last word, upper-cased. Use `[...word][0]` for the first character so accented letters work (`élodie dupont` gives `ÉD`).
**`memberSince.ts`:** `memberSince(iso: string | null | undefined): string | null`: the calendar month and year **in Indian Standard Time (UTC+05:30)** written `Mon YYYY` with the month names written out in code (`Jan Feb Mar Apr May Jun Jul Aug Sep Oct Nov Dec`; do **not** use `Intl` or `toLocaleDateString`: en-GB prints `Sept`). Steps: trim; empty or null gives `null`; a string with a time (`T` followed by hh:mm) but **no zone designator** (`Z`, or a `+hh:mm`/`-hh:mm` offset at the end) is read as **UTC** (append `Z`), never as the machine's local time; parse with `new Date`; an invalid date gives `null`; add 330 minutes and read the **UTC** month and year of the shifted date. Examples: `2025-10-14T09:30:00+05:30` gives `Oct 2025`; `2025-10-31T18:30:00Z` gives `Nov 2025`; `2025-10-31T18:29:59Z` gives `Oct 2025`; `2025-10-31T20:00:00` gives `Nov 2025`; `2025-09-10T00:00:00Z` gives `Sep 2025`; `2025-03-05` gives `Mar 2025`.
**`profileNav.ts`:** types `ProfileNavChild { id: string; label: string; path: string }` and `ProfileNavItem { id: string; label: string; path: string; icon: LucideIcon; children?: ReadonlyArray<ProfileNavChild> }`; `export const PROFILE_NAV: ReadonlyArray<ProfileNavItem>`, in this order, each `path` from the `paths` builder named in brackets and each `icon` from lucide-react: `personal` / `Personal Information` [`profilePersonal`] `UserRound`; `family` / `Family Members` [`profileFamily`] `Users`; `connected-accounts` / `Connected Accounts` [`profileConnectedAccounts`] `Link2`; `settings` / `Settings` [`profileSettings`] `Settings`, with `children`: `notifications` / `Notifications` [`profileNotifications`], `preferences` / `Preferences` [`profilePreferences`], `security` / `Security` [`profileSecurity`], `import-history` / `Import History` [`profileImportHistory`]; `subscription` / `Subscription & Billing` [`profileSubscription`] `CreditCard`; `tax` / `Tax Information` [`profileTax`] `FileText`; `data-privacy` / `Data & Privacy` [`profileDataPrivacy`] `ShieldCheck`. Also `export function isNavItemCurrent(item: ProfileNavItem, pathname: string): boolean`: strip trailing slashes from `pathname` and lower-case both; true when equal to the item's path, or when the item **has children** and the pathname starts with the item's path followed by `/` (so `/profile/settings/security` is current for Settings, `/profile/family/extra` is not current for Family, `/profile/settings-x` is not current for Settings).
