Sub-project 2 · Look-through engine

Portfolio Disclosure Gaps

The look-through engine reads each fund house's monthly portfolio file: every stock, bond and cash line a fund holds. A daily job downloads these files on its own. For 7 of the 57 fund houses it cannot, so someone downloads the file in a browser each month and imports it with one command. This page covers what that is, why, which attributes depend on it, and the options.

What this is

SEBI requires every fund house to publish each scheme's full portfolio every month, shortly after month-end. The engine collects these files so it can answer questions a fund's category label cannot: how much Reliance does a client really own across all their funds, and how much of the portfolio is large-cap.

For 45 fund houses a daily job finds the file on the AMC's site, downloads it, reads the stock lines, matches each sheet to the right scheme, checks that the weights add up to about 100%, and stores the result. For the 7 below, the job cannot fetch the file. Each month a person does that one step in a browser. Everything after the download is the same code as the automatic path, with the same checks.

This is the same arrangement the fund-manager section (attribute 04) already uses for its factsheets. The two chores fall in the same week of each month.

Which attributes depend on it

AttributeWhat it needs from the monthly files
06 · Overall stock holdingsReads every fund's stock list to total each stock across the portfolio. A manual AMC's funds add nothing until its file is in.
02 · Large, mid and small capClassifies the stocks inside each fund. Same dependency.
10 · Portfolio overlapCompares funds pair by pair. A fund with no file cannot appear in the heatmap.
13 · Asset allocationAdds up equity, debt, gold and cash from what each fund discloses. A missing fund is counted as uncovered.
15 · P/E and P/BNeeds the stocks a client holds through funds. Shown only when at least 70% of the equity has data.

When a fund has no file, it is not dropped. The Analytics page shows a banner such as "Based on 62% of your portfolio", names the uncovered funds, and splits them into "not published yet" and "not available from this AMC". A manual AMC with no file at all is counted as "not available from this AMC" until its first import.

Do we have to do this every month?

Yes, for as long as these 7 stay manual. Fund houses publish by about the 10th of the following month, so the routine runs once, around days 10 to 12.

Daily job
  • Runs at 05:45 IST on days 1 to 20, once the Terraform is applied at the end of the build.
  • Creates a "waiting for upload" row for each manual scheme that has no file for the latest month-end.
  • Alerts on days 10 and 20 if rows are still waiting, naming the fund houses.
If a month is missed
  • The funds keep showing the last month's data, tagged "older than 60 days" once they pass that age.
  • The coverage banner says so.
  • The newest file is never deleted, even if it is old.
Next due
  • October month-end files, published about 10 Nov.
  • The 10 Nov fund-manager factsheet job falls on the same day. Plan both chores for that week.

Effort: 7 fund houses. Edelweiss, Mahindra, Invesco, ITI and Bandhan are one file each. JM Financial and HSBC publish one file per scheme, which is the bulk of the work: about 17 for JM, and HSBC's count has not been taken. I have not timed it. The comparable factsheet routine was estimated at about 45 minutes.

How the monthly import works

flowchart LR
  a["Month-end
AMC publishes by ~10th"] --> b["You download the file
in a normal browser"]
  b --> c["One import command
per fund house"]
  c --> d["Checks: real workbook, date,
scheme match, weights ~100%"]
  d -->|all pass| e["Waiting rows become
WRITTEN batches"]
  d -->|any check fails| f["Nothing is written
for that call"]
  e --> g["06:30 recompute
next morning"]
  g --> h["Client sees it
in Analytics"]

The command writes all the files in one call or none of them. It refuses a file that is not a workbook, a date in the future, or a date that is not a month-end unless you say so. It never guesses weights: a sheet whose weights do not add up is stored as failed and is never shown to clients.

Why manual, and what else we could do

Why we chose it. It is the only route that is reliable today and respects the project's access rules. It reuses the same parser, matcher and weight checks as the automatic path, so the data is held to the same standard. It also matches how attribute 04 already works, so one team routine covers both.

The monthly routine

Download each file in a normal browser, unchanged. Keep them outside the repo (for example Desktop\Unifolio\Portfolio Disclosures\<month>\). Do not open and re-save them. Then, from backend\, run once per fund house, using the month-end date:

Fund houseCommand arguments for scripts/jobs/import_manual_portfolio_disclosures.py
Edelweiss--amc "Edelweiss Mutual Fund" --file Edelweiss.xlsx --as-of 2026-09-30
Mahindra Manulife--amc "Mahindra Manulife Mutual Fund" --file Mahindra.xlsx --as-of 2026-09-30
Invesco--amc "Invesco Mutual Fund" --file Invesco.xlsx --as-of 2026-09-30
ITI--amc "ITI Mutual Fund" --file ITI.xlsx --as-of 2026-09-30
JM Financial--amc "JM Financial Mutual Fund" --file JM-Large-Cap.xlsx --file JM-Mid-Cap.xlsx (one --file per scheme) --as-of 2026-09-30
HSBC--amc "HSBC Mutual Fund" --file HSBC-scheme-1.xlsx --file HSBC-scheme-2.xlsx (one --file per scheme) --as-of 2026-09-30
Bandhan--amc "Bandhan Mutual Fund" --file Bandhan.xlsx --as-of 2026-09-30

It prints matched=N unmatched=M schemes_written=K. Compare the numbers with last month's. A file for an earlier month needs --allow-old, and a date that is not a month-end needs --allow-any-date. To see what is still owed, count the waiting rows (status awaiting_manual_upload) for the latest month-end.
