06

Picker-to-result dispatch logic

A pure function of backend-provided scenario metadata — never inferred from scenario name or category alone.

if scenario.scenarioType === "HYPOTHETICAL" → hypothetical
else if scenario.hadRedemptionFreezeSchemes?.length → redemption_freeze
else if scenario.parentScenarioId === null && scenario.hasPhases → multi_phase
else → standard

    }

Invariant Step 2 guarantees: every active scheme gets exactly one scenario_scheme_results row per non-hypothetical scenario — real or proxied, never a missing row. This is what keeps Step 3's serving query branch-free and is why the frontend never needs a "no row at all" fallback, only the is_proxied display check already covered in the states table above.
