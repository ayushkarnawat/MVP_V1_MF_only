flowchart TB

    Section --> Toggle["Monthly / Yearly segmented toggle\n(switches same response's monthly[]/yearly[],\nno second fetch)"]

Formulas (restated, not re-derived — full worked example in the backend doc): net_invested = total_invested − total_withdrawn; absolute_gain = current_value + total_withdrawn − total_invested.

Explicitly out of scope: fund-level drill-down (confirmed scope fork, "Future phase 2" in the backend doc, no revisit trigger); switch/STP excluded from totals (cash_flow.py's existing classification); gift/bonus transactions excluded (existing "not cash" precedent).
05

Schema & data flow — backend grounding

Added for implementation handoff. No new database table exists for this attribute — everything below is computed on-the-fly from the household's existing transactions and folio/holdings data at request time, the same posture sip.py already uses. Not part of the originally approved mockup above — purely explanatory, grounded verbatim in 2026-10-07-sub-project-1-planning.md's "Attribute 14" section.

flowchart TB
    Txns[("transactions\n(existing table)")] --> Classify["cash_flow.py's existing\n_DEBIT_TYPES / _CREDIT_TYPES\n(reused as-is, not redefined)"]
