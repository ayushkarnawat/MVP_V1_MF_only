Attribute 04 · Fund manager allocation

Factsheet Access Gaps

The fund-manager section reads each fund house's monthly factsheet PDF. The plan assumed a monthly job could download nearly all of them on its own. For 15 of the 55 fund houses it can't: 10 now need someone to download the factsheet by hand each month, and 5 publish no usable factsheet at all. This page covers why, what changed from the plan, and the options from here.

How the feature is meant to work

Every fund house (AMC) publishes a monthly factsheet: a long PDF with one page per fund, listing who manages it and since when. AMFI's website keeps a directory linking to each AMC's factsheet page. Once a month, a background job goes to each AMC's page, finds the newest factsheet, checks it is really this month's factsheet (enough fund pages, an "as on" date within 45 days), reads the manager names with a reader written for that AMC's layout, and saves them against the matching funds.

If an AMC can't be read, the job raises an alert (FUND_MANAGER_ALERT, with a CloudWatch alarm), and that AMC's funds show "not available yet" instead of a wrong or made-up manager. Manager data older than three months stops being shown.

What the plan assumed, and what happened

The plan (8–9 Oct)
  • Only HDFC and Kotak by hand. Edelweiss was on the manual list in the spec but its page served the PDF normally on 9 Oct, so it moved to automatic.
  • The other 53 fund houses automatic, onboarded in five batches (Runs 3–7).
  • No AMC pushed past staging: every fund house onboarded before release.
  • A factsheet is found as a link on the AMC's web page.
What actually happened
  • Most AMC pages don't contain the PDF link at all. The browser builds the list with JavaScript after the page loads.
  • For most of them, Codex found the request the page itself makes for its download list and used that directly. That's how 40 became automatic.
  • For 8 more, that request was refused, needed a key, or the site blocked scripted visitors. They joined HDFC and Kotak as manual: 10 in total.
  • 5 publish no current factsheet anywhere, so they're off.

How it unfolded

  1. 8 Oct · specHDFC, Kotak and Edelweiss expected to need manual intake; every other AMC expected to be automatic.
  2. 9 Oct · catalogueA scripted pass over all 55 AMC pages: dozens show "no factsheet link in the HTML", meaning the links are built by JavaScript. Edelweiss turns out to be downloadable and moves to automatic.
  3. 10 Oct · Run 5Axis, ICICI Prudential, ITI, Trust and WhiteOak refuse the requests (403 "access denied", Cloudflare/CloudFront bot protection, or error pages). You chose monthly manual import and uploaded the five factsheets.
  4. 10 Oct · Run 7Bandhan's download list needs an API key (401). The key is visible in the site's code, but using it would be getting around their access control, so a "no workarounds" rule went into the plan. Invesco (403) and JM Financial (406, AppTrana firewall) also block scripts. You chose manual import and uploaded the three factsheets.
  5. 10 Oct · Run 8Mahindra Manulife's list is encrypted in transit but served to anyone; the page decodes it in every visitor's browser. You chose to keep it automatic (no credentials involved).
  6. 10 Oct · Run 9AlphaGrep, IL&FS, Lakshya and Monarch confirmed to publish no factsheet; Bajaj still only has a July file. All five left off with the evidence recorded. Samco started publishing again and was switched on.

How we deviated from the plan

Scope and effort
  • Manual AMCs: 2 → 10. Monthly ops work goes from 3 files to 11.
  • 5 AMCs not onboarded, against the plan's "every AMC before staging". 33 live funds affected.
  • Onboarding took 9 runs, not 7, because batches grew too large and needed splitting.
  • Each manual AMC still needed its own reader, built from the files you uploaded.
Rules added to the plan
  • No access-control workarounds (Run 7): no keys, logins or tokens a normal visitor isn't given.
  • Encrypted-but-public lists are allowed (Run 8, Mahindra), since no credentials are involved.
  • Below 90% coverage is fine when every missing fund has a reason (Run 7).
  • No headless browser and no new dependencies in the job.
Machinery the plan didn't have
  • Several files per month for one AMC (HDFC, Mirae, UTI, SBI, Navi).
  • Reading word positions for table layouts (Axis, ICICI, Franklin, 360 ONE).
  • A per-AMC minimum fund count for one-fund AMCs (ASK).
  • Per-AMC date patterns, and many new date formats.

Risks that come with the current setup

Someone forgets a month

Manager data is only as fresh as the last hand import. After three months without one, those funds' managers stop showing. There is no reminder or alert for a missed manual import yet.

Automatic AMCs may be blocked from AWS

The 40 automatic AMCs were verified from a normal network. Some may refuse requests from AWS addresses. The job's alert will name any that fail on the first staging run; each would then move to manual or get fixed.

Sites change

The download requests found for 40 AMCs are the sites' own internal requests. A redesign can break one; the job alerts on that AMC, and the others keep working.

Options from here

These aren't mutually exclusive. The 5 "off" AMCs can only be covered by option D; the other options apply to the 10 manual ones.

A

Keep the monthly hand import

in place now
How
Each month: download 11 PDFs in a browser, run import_manual_fund_managers.py once per AMC, and compare the matched count with last month.
Cost
About 45 minutes of ops time a month. Nothing new to build.
Good
Works today, for certain. Uses the sites the way they intend. Same reader and checks as the automatic job.
Weak
Depends on a person every month; a missed month goes unnoticed until data ages out.
B

Make the hand import easier and watched

small build
How
An admin upload screen instead of a command line; a checklist with each AMC's download page; an alert when a manual AMC's latest import is older than ~40 days.
Cost
A small backend + admin UI task, and one CloudWatch alarm.
Good
Turns option A into a 15–20 minute routine that can't silently lapse.
Weak
Still manual.
C

Ask the fund houses for access

business effort
How
Request an official API key (Bandhan), allow-listing of our fixed outbound IP (staging already uses one NAT address), or a monthly email of the factsheet. Start with the largest: ICICI (158), Kotak (120), HDFC (112), Axis and Bandhan (89 each).
Cost
Outreach time; replies may take weeks or never come.
Good
Legitimate and durable. Each yes moves one AMC to automatic with almost no code (the readers exist).
Weak
Slow and uncertain; one conversation per fund house.
D

License fund-manager data from a data vendor

needs research
How
Indian mutual-fund data providers sell scheme-level data that can include fund managers and their history. A feed would replace or back up the factsheet reading.
Cost
Unknown: licence fees and display terms need a quote. Changes A04's data source.
Good
The only option that also covers the 5 "off" AMCs. No scraping, no monthly chores.
Weak
Recurring cost, a vendor dependency, and licence limits on showing the data to users.
E

Run a real browser inside the monthly job

not recommended
How
Add a headless browser (e.g. Playwright) so pages that build their links with JavaScript work, Kotak being the main candidate.
Cost
A new dependency, a much larger job container, slower runs.
Good
Could automate the few pages that only need JavaScript and aren't actively blocking.
Weak
Doesn't help with the 403/406 sites: their bot protection is designed to stop exactly this, often blocks AWS addresses anyway, and pushing past it conflicts with the no-workarounds rule.
F

Drop the smallest manual AMCs

trade-off
How
Leave Trust (11), JM Financial (17) and ITI (21) as "not available yet" to save ops time.
Cost
49 live funds lose manager data.
Good
Cuts the monthly routine from 11 files to 8.
Weak
Saves only a few minutes; the readers already exist.

Recommendation

  1. Now, for staging: keep A. The readers and import script are built and tested on all 10 files.
  2. Soon after: build B, so the monthly routine is quick and a missed month raises an alert.
  3. In parallel: start C with the five largest fund houses, and get a quote for D. D is the only way to cover the 33 funds with no factsheet, and the only route to zero monthly work.
  4. Skip E unless one specific AMC turns out to need only JavaScript, with no bot protection.
  5. On the first staging run: read the job's alerts to see whether any of the 40 automatic AMCs are blocked from AWS.
