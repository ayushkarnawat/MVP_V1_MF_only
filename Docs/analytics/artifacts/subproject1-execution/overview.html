Order

Run order and why

flowchart LR
  a14["1 · A14<br/>no schema<br/>proves the 8th-section path"] --> a12["2 · A12<br/>backend only<br/>re-keys benchmark rows"]
  a12 --> a09["3 · A09<br/>2 tables<br/>reuses existing modules"]
  a09 --> a04["4 · A04 core<br/>tasks 1–7, 21"]
  a04 --> a11["5 · A11<br/>heaviest, needs the backfill"]
  a12 -. "TRI rows + deep backfill" .-> a11
  a04 --> r["A04 research batch<br/>tasks 8–20, registry file only"]
  r -. "runs alongside" .-> a11
  • A14 first: no migration, and it exercises the full section pipeline (compute → analytics_sections → generic endpoint → screen) that 09 and 04 reuse. The handoff guide suggests the same.
  • A12 before A11: A11's scenario benchmarks read TRI only, and scenarios before 2016 need A12's TRI history from 1990.
  • 09 before 04: 09 is self-contained. 04 needs real-PDF fitting and live AMC tracing, which takes longer than the code.
  • A11 last: biggest surface, and the NAV backfill is an operational step with its own runbook. Starting it last lets the backfill's small-batch test run while 04's research batch finishes.
  • Serial, not parallel: one Codex session at a time (your setting in delegation-log.md), and the plans share files (table below).
