Why one shared function, not five: the engine spec's own section 00 write-up names this explicitly — "stock exposure, sector split, market-cap split, asset allocation, overlap, P/E, P/B... read from the same look-through table instead of each feature re-deriving it." The naive-sum trap it's designed to prevent: Reliance at 8%/6%/5% across three funds is not 19% client exposure — only 6.55%, once each fund's own portfolio share is applied.

3.2% of equity excluded from P/E (negative earnings) — P/B unaffected.
Integration, not just data availability (spec §7.3): stock_master is a second, independent daily refresh pipeline — not a stage of the AMC disclosure engine. ISIN universe = every ISIN in scheme_holdings ∪ Nifty 50/500 constituents, re-derived each run. Per-ISIN fallback chain: NSE security master → Yahoo quoteSummary → screener.in (only on a Yahoo miss) → NULL + footnote if all fail (e.g. a delisted/merged ISIN). This attribute's cache invalidates on either a fresh AMC disclosure or a fresher stock_master price — two independent triggers, not one.
