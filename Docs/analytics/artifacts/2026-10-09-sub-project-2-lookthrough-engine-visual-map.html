02

Data model — 2 tables

Grain fixed at (scheme, as-of-date), not (AMC, month) — the one real gap this design's pressure-test found and fixed. See §05.

erDiagram
    SCHEMES ||--o{ DISCLOSURE_BATCHES : "one per (scheme, as_of_date)"
    DISCLOSURE_BATCHES ||--o{ SCHEME_HOLDINGS : "delete+reinsert per batch_id"
    DISCLOSURE_BATCHES {
        uuid scheme_id FK
        date as_of_date "verbatim from source, never coerced to month-end"
        string amc_name "denormalized for adapter queries"
        enum status "PENDING|FETCHED|PARSED|WRITTEN|FAILED|AWAITING_MANUAL_UPLOAD"
        string source_url
        string raw_file_reference "S3 key of original file"
        jsonb parse_errors "nullable, [{file, error}] per failed sheet/file in a bundle"
    }
    SCHEME_HOLDINGS {
        uuid batch_id FK
        string instrument_name "verbatim"
        string isin "nullable -- cash/CBLO/TREPS/Net Receivables have none"
        string sector_raw "verbatim, NOT normalized at write time"
        numeric quantity
        numeric market_value "normalized to rupees, never lakhs/crores"
        numeric pct_to_nav
    }
Why not a third table? disclosure_batches.status + source_url + raw_file_reference + parse_errors already carry everything a separate file/job-tracking table would. The AWAITING_MANUAL_UPLOAD status gives this same table double duty as the manual-upload queue — same precedent as attribute 04's factsheet manual path.

Five-stage pipeline, per AMC adapter

Generic (config row) by default; custom code only where Locate or Parse is genuinely non-formulaic.

    N --> W["5 · Write

Pressure-test: the one real gap, and the refinements

FoundFix
Real gap: (AMC, month) grain collides when one AMC mixes disclosure cadences per scheme (Canara Robeco: monthly equity, fortnightly some debt)Re-key disclosure_batches to (scheme, as_of_date); still 2 tables
Multi-file bundle status as free text ("143/151 parsed")Structured parse_errors JSONB, [{file, error}]
Bespoke Python per AMC as the defaultConfig-driven adapter as default; custom code only where non-formulaic
Per-AMC publishing-lag schedule configFlat retry-until-found window, reusing existing EventBridge/ECS Fargate jobs
A new one-off scheme-name matcherReuse the hybrid layered-matching pattern + match_method/match_confidence columns already live on scheme_fund_managers
Resuming partial state on bundle retryRejected — always reprocess the full bundle from scratch, removes a whole bug class
