**PGIM India Mutual Fund — BOT_BLOCKED.** I first requested the official monthly-portfolio URL with a desktop browser user-agent. The response was HTTP 403. I then attempted browser retrieval of that same route; it was rejected as well. Search indexing showed the page title and a current “PGIM INDIA EQUITY SAVINGS FUND Aug 2026” entry, which establishes that the target page exists but does not establish a reusable endpoint or validate the workbook. With both required access methods blocked, I did not substitute an aggregator-hosted copy.

**WhiteOak Capital Mutual Fund — NEEDS_INVESTIGATION.** I searched the official domain for portfolio/monthly-disclosure routes, tried the likely downloads/statutory areas by plain HTTP, and inspected the rendered-site path/network behavior. Current 2026 monthly entries were visible only through independent download indexes; I could not recover and download a stable `whiteoakcapitalmf.com` file URL. A later pass should trace the downloads UI in a full local Chromium session or inspect its application bundle/API configuration.

**Sundaram Mutual Fund — NEEDS_INVESTIGATION.** I followed the official statutory-disclosure references from Sundaram scheme documents and tried both the statutory and financial/half-yearly pages. Plain HTML yielded the half-yearly portfolio area, while the monthly UI/file link remained undiscoverable; the browser attempt did not reveal a stable downloadable endpoint. August 2026 scheme holdings are clearly published and consumed elsewhere, so this is an endpoint-discovery failure rather than evidence of missing content. A later pass should drive the exact “Monthly Portfolios” state in a full browser and retain the XHR/CDN request.
